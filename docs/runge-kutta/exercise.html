Exercise: Runge–Kutta and adaptive step size

Goal

By the end of this exercise you should be able to:

  • take one step of the midpoint, Heun and classical RK4 methods by hand, and write each as a short function,
  • read the order of a method off a table or a log–log plot of error against step size, and compare methods by the number of function evaluations,
  • use a conserved quantity (Lotka–Volterra) to detect the error of an ODE solver,
  • explain how an embedded pair estimates the error of a step, and how an adaptive solver accepts or rejects the step and chooses the next one,
  • say what rtol and atol mean, choose them for a model, and check a result by tightening them,
  • use the library solvers (deSolve::ode, scipy.integrate.solve_ivp, ode_solvers), and locate events such as the peak of an epidemic.

The by-hand part needs pen, paper and a pocket calculator. The code part checks the hand answers and then works at sizes where only code works.

Background

To solve \(y' = f(t, y)\), \(y(t_0) = y_0\) with step \(h\):

  1. Euler (order 1, 1 evaluation of \(f\)): \(y_{n+1} = y_n + h k_1\), \(k_1 = f(t_n, y_n)\).
  2. Midpoint (order 2, 2 evaluations): \(k_2 = f(t_n + \tfrac h2, y_n + \tfrac h2 k_1)\), \(y_{n+1} = y_n + h k_2\).
  3. Heun (order 2, 2 evaluations): \(k_2 = f(t_n + h, y_n + h k_1)\), \(y_{n+1} = y_n + \tfrac h2 (k_1 + k_2)\).
  4. RK4 (order 4, 4 evaluations): \(k_2 = f(t_n + \tfrac h2, y_n + \tfrac h2 k_1)\), \(k_3 = f(t_n + \tfrac h2, y_n + \tfrac h2 k_2)\), \(k_4 = f(t_n + h, y_n + h k_3)\), \(y_{n+1} = y_n + \tfrac h6 (k_1 + 2k_2 + 2k_3 + k_4)\).
  5. Order. A method of order \(p\) has global error \(\approx C h^p\). Halving \(h\) divides the error by \(2^p\), so \(p \approx \log_2(\text{err}(h)/\text{err}(h/2))\), and on a log–log plot the error is a line with slope \(p\). The error of a single step is \(\propto h^{p+1}\).
  6. Embedded pair. Two answers of orders \(q\) and \(q+1\) from the same stages (Euler and Heun; or orders 4 and 5 in Dormand–Prince). Their difference estimates the error of the step. With the allowed error \(\text{sc}_i = \texttt{atol} + \texttt{rtol}\cdot\max(|y_{n,i}|, |y_{n+1,i}|)\) per component, the scaled error is \[\text{err} = \sqrt{\tfrac1m \textstyle\sum_{i=1}^m \big(\text{est}_i / \text{sc}_i\big)^2}.\] The step is accepted if \(\text{err} \le 1\), otherwise rejected and retried. Either way the next step is \(h_{\text{new}} = h\cdot \min\!\big(5, \max(0.2,\ 0.9\, \text{err}^{-1/(q+1)})\big)\).
  7. Library solvers. R: deSolve::ode with method = "ode45" (Dormand–Prince, defaults rtol = atol = 1e-6) or "rk4" (fixed step = spacing of times, see rk). Python: scipy.integrate.solve_ivp with method="RK45" (the default; rtol=1e-3, atol=1e-6). Rust: the ode_solvers crate with Dopri5 (adaptive) and Rk4 (fixed step); you give both tolerances.

The running examples:

  • Logistic OD curve \(N' = rN(1 - N/K)\), \(r = 0.8\) per hour, \(K = 1.2\), \(N_0 = 0.05\); exact \(N(t) = K / \big(1 + (K/N_0 - 1)e^{-rt}\big)\).
  • Drug clearance \(C' = -0.8\, C\), \(C_0 = 10\) mg/L; exact \(C(t) = 10 e^{-0.8t}\).
  • SIR epidemic (as in Initial value problems and Euler’s method): \(S' = -\beta SI/N\), \(I' = \beta SI/N - \gamma I\), \(R' = \gamma I\) with \(N = 10\,000\) people, \(\beta = 0.3\) and \(\gamma = 0.1\) per day, \((S, I, R)(0) = (9990, 10, 0)\). Exact peak \(I_{\max} = 3007.961\).
  • Lotka–Volterra (hares \(x\), lynx \(y\)): \(x' = ax - bxy\), \(y' = cxy - dy\) with \(a = 1\), \(b = 0.1\), \(c = 0.075\), \(d = 1.5\) per year, \((x, y)(0) = (10, 5)\).
  • Repressilator (Elowitz & Leibler 2000, dimensionless): \(m_i' = -m_i + \alpha/(1 + p_j^{\,n}) + \alpha_0\), \(p_i' = -\beta(p_i - m_i)\), \((i, j) = (1,3), (2,1), (3,2)\), with \(\alpha = 216\), \(\alpha_0 = 0.216\), \(\beta = 5\), \(n = 2\), start \(m = (1, 0, 0)\), \(p = (0, 0, 0)\).

// rust/examples/runge_kutta_background.rs  —  cargo run --example runge_kutta_background
// Background: one hand-written RK4 step, then the library solver (ode_solvers::Dopri5)
use ode_solvers::continuous_output_model::ContinuousOutputModel;
use ode_solvers::{Dopri5, System, Vector1};

fn f(_t: f64, n: f64) -> f64 {
    0.8 * n * (1.0 - n / 1.2) // logistic, per hour
}

fn rk4_step(f: fn(f64, f64) -> f64, t: f64, y: f64, h: f64) -> f64 {
    let k1 = f(t, y);
    let k2 = f(t + h / 2.0, y + h / 2.0 * k1);
    let k3 = f(t + h / 2.0, y + h / 2.0 * k2);
    let k4 = f(t + h, y + h * k3);
    y + h / 6.0 * (k1 + 2.0 * k2 + 2.0 * k3 + k4)
}

// ode_solvers wants the ODE as a type implementing the System trait
struct Logistic;
impl System<f64, Vector1<f64>> for Logistic {
    fn system(&self, t: f64, y: &Vector1<f64>, dy: &mut Vector1<f64>) {
        dy[0] = f(t, y[0]);
    }
}

fn main() {
    println!("{}", rk4_step(f, 0.0, 0.05, 1.0)); // one RK4 step of h = 1

    // Dopri5::new(system, t0, t_end, output spacing, y0, rtol, atol)
    let mut solver = Dopri5::new(Logistic, 0.0, 10.0, 1.0, Vector1::new(0.05), 1e-8, 1e-10);
    let mut dense = ContinuousOutputModel::default(); // the solution at any t
    solver.integrate_with_continuous_output_model(&mut dense).unwrap();
    for t in [0.0, 1.0, 10.0] {
        println!("t = {:>2}: N = {:.7}", t, dense.evaluate(t).unwrap()[0]);
    }
}

// Output:

deSolve::ode wants the right-hand side as func(t, y, parms) returning a list; solve_ivp wants fun(t, y) returning an array; ode_solvers wants a type that implements its System trait. Rust prints numbers in its own format (e.g. 1e-3 rather than 1e-03); the values are the same unless the text says otherwise.

By hand

B1. Midpoint and Heun. Drug clearance \(C' = -0.8\,C\), \(C_0 = 10\) mg/L, one step of \(h = 0.5\) hours. (a) Take one Euler, one midpoint and one Heun step. Write down \(k_1\), \(k_2\) and the point where \(k_2\) is evaluated for each. (b) Compare with the exact \(C(0.5) = 10e^{-0.4} = 6.70320\). Give the error of each method. (c) Show that for \(C' = -kC\) midpoint and Heun both give \(C_1 = C_0(1 + z + z^2/2)\) with \(z = -kh\). Which Taylor polynomial is this?

B2. One RK4 step. Same problem and step. (a) Compute \(k_1, k_2, k_3, k_4\) (fill in a table: stage, point, slope) and \(C_1\). (b) Compare with the exact value. How many times smaller is the error than Heun’s? (c) The error of one step is \(\propto h^5\). Predict the error of a single RK4 step with \(h = 0.25\), then check it: the exact value is \(10e^{-0.2} = 8.187308\).

B3. Reading the order. Errors in \(N(10)\) for the logistic curve:

\(h\) 0.5 0.25 0.125
Heun \(1.51\times10^{-3}\) \(3.36\times10^{-4}\) \(8.05\times10^{-5}\)
RK4 \(9.25\times10^{-6}\) \(5.31\times10^{-7}\) \(3.20\times10^{-8}\)
  1. Estimate the order of each method from consecutive ratios.
  2. Predict both errors for \(h = 0.0625\).
  3. About how many function evaluations does each method need (from \(t = 0\) to \(10\)) for an error of \(10^{-8}\)?

B4. An embedded pair by hand. Clearance again, from \(C_0 = 10\) with \(h = 0.5\), using Euler (order 1) and Heun (order 2) from B1 as a pair, with rtol = 0.01 and atol = 0. (a) What is the error estimate? Compare it with the true errors of Euler and Heun. Which of the two does it estimate? (b) Compute \(\text{sc}\), the scaled error err and decide: accept or reject? Compute the next step size. (c) The error estimate of this pair is \(\propto h^2\). Predict err for the new step, then compute it.

B5. What rtol and atol mean. SIR at \(t = 0\): \(S = 9990\), \(I = 10\), \(R = 0\) people. (a) With rtol = 1e-3 and atol = 1e-6, what error is allowed in one step for each of \(S\), \(I\) and \(R\)? (b) A colleague writes the same model in fractions of the population (\(S = 0.999\), \(I = 0.001\)) and keeps atol = 1e-6. What error does this allow in \(I\), in people? Is that still fine? (c) Another colleague sets atol = 10 (“ten people do not matter in a town of 10 000”). What error does this allow in \(I\) at \(t = 0\), relative to \(I\) itself? What could go wrong? (d) A signalling model measures concentrations in mol/L; the important species is around \(10^{-9}\) M. What is wrong with atol = 1e-6? Give two fixes.

B6. A conserved quantity. Lotka–Volterra with \(V(x, y) = c x - d \ln x + b y - a \ln y\). (a) Use the chain rule, \(\frac{dV}{dt} = \frac{\partial V}{\partial x} x' + \frac{\partial V}{\partial y} y'\), to show that \(dV/dt = 0\) along every solution. (b) Compute \(V\) at the start \((10, 5)\) and at the equilibrium \((x^*, y^*) = (d/c,\ a/b)\). (Use \(\ln 2 = 0.6931\), \(\ln 5 = 1.6094\), \(\ln 10 = 2.3026\).) (c) \(V\) is smallest at the equilibrium, and the orbits are the curves $V = $ constant around it. Euler makes \(V\) increase. What does the plotted orbit do? Why is that a biologically misleading picture?

B7. Events. For SIR let \(g = \beta S/N - \gamma\). (a) Show that \(I' = g\, I\), so \(I\) peaks where \(g\) changes sign from \(+\) to \(-\). What is \(S\) at the peak? (b) An adaptive solver (rtol = 1e-4) takes two consecutive steps ending at \(t = 35.16\) with \(S = 4426.1\) and at \(t = 42.04\) with \(S = 2404.5\). Compute \(g\) at both, and locate the peak by linear interpolation of \(g\). The true peak time is \(38.355\) days; why is your estimate off, and what does a solver do instead? (c) Lynx numbers rise above 20 for about 0.8 years in each 5.5-year cycle. A program only checks \(y - 20\) at the end of each step, and its steps are 2.5 years long. Can it miss the event? What two remedies are there?

C1. Write the methods. (a) Write step functions euler_step, midpoint_step, heun_step, rk4_step with arguments (f, t, y, h), and a driver rk_solve(step, f, t0, y0, h, n) that takes n fixed steps and returns all times and states. C5. The library on the repressilator. (a) Solve the repressilator to \(t = 50\) with Dormand–Prince (ode45 / RK45 / Dopri5) and rtol = atol \(= 10^{-3}, \dots, 10^{-9}\). (root finding is not available with ode45 in deSolve); in Python solve_ivp(..., events=...); in Rust, ode_solvers has no event location, so scan the dense output for a sign change and refine it by bisection. E1. (four slopes) On the logistic curve with RK4 and \(h = 1\), press next stage four times. For each stage, write down where the slope is evaluated and its value, and say which earlier slope leads to the point. Why is \(k_3\) larger than \(k_2\), although both are taken at \(t = 0.5\)? Compare the combined value with the exact one, then switch to Euler, Midpoint and Heun at the same \(h\) and compare the errors of the single step.

Answer E1

\(k_1 = f(0, 0.05) = 0.03833\); \(k_2 = f(0.5, 0.06917) = 0.05214\), reached along slope \(k_1\); \(k_3 = f(0.5, 0.07607) = 0.05700\), reached along \(k_2\); \(k_4 = f(1, 0.10700) = 0.07797\), reached along \(k_3\). The curve bends upwards, so \(k_1\) (the slope at the start) underestimates the rise; the point for \(k_3\) is built with the steeper \(k_2\), so it lies higher, where the logistic curve is steeper. // rust/examples/runge_kutta_c1.rs  —  cargo run --example runge_kutta_c1
// C1: midpoint, Heun and RK4 by hand; order on the logistic curve
type Rhs = dyn Fn(f64, &[f64]) -> Vec<f64>;
type Step = fn(&Rhs, f64, &[f64], f64) -> Vec<f64>;

// y + a * k, element by element (R and numpy do this with `y + a * k`)
fn axpy(y: &[f64], a: f64, k: &[f64]) -> Vec<f64> {
    y.iter().zip(k).map(|(yi, ki)| yi + a * ki).collect()
}

fn euler_step(f: &Rhs, t: f64, y: &[f64], h: f64) -> Vec<f64> {
    axpy(y, h, &f(t, y))
}
fn midpoint_step(f: &Rhs, t: f64, y: &[f64], h: f64) -> Vec<f64> {
    let k1 = f(t, y);
    let k2 = f(t + h / 2.0, &axpy(y, h / 2.0, &k1));
    axpy(y, h, &k2)
}
fn heun_step(f: &Rhs, t: f64, y: &[f64], h: f64) -> Vec<f64> {
    let k1 = f(t, y);
    let k2 = f(t + h, &axpy(y, h, &k1));
    let k: Vec<f64> = k1.iter().zip(&k2).map(|(a, b)| a + b).collect();
    axpy(y, h / 2.0, &k)
}
fn rk4_step(f: &Rhs, t: f64, y: &[f64], h: f64) -> Vec<f64> {
    let k1 = f(t, y);
    let k2 = f(t + h / 2.0, &axpy(y, h / 2.0, &k1));
    let k3 = f(t + h / 2.0, &axpy(y, h / 2.0, &k2));
    let k4 = f(t + h, &axpy(y, h, &k3));
    let k: Vec<f64> = (0..y.len()).map(|i| k1[i] + 2.0 * k2[i] + 2.0 * k3[i] + k4[i]).collect();
    axpy(y, h / 6.0, &k)
}
// n fixed steps of any method; returns the final state
fn rk_solve(step: Step, f: &Rhs, t0: f64, y0: &[f64], h: f64, n: usize) -> Vec<f64> {
    let mut y = y0.to_vec();
    for i in 0..n {
        y = step(f, t0 + i as f64 * h, &y, h);
    }
    y
}

struct Run { t: Vec<f64>, h: Vec<f64>, y: Vec<Vec<f64>>, nrej: usize }

fn adapt_heun(f: &dyn Fn(f64, &[f64]) -> Vec<f64>, mut t: f64, y0: &[f64], tend: f64,
              mut h: f64, rtol: f64, atol: f64) -> Run {
    let mut y = y0.to_vec();
    let mut run = Run { t: vec![t], h: vec![], y: vec![y.clone()], nrej: 0 };
    let m = y.len();
    while t < tend {
        h = h.min(tend - t);
        let k1 = f(t, &y);
        let ye: Vec<f64> = (0..m).map(|i| y[i] + h * k1[i]).collect(); // Euler, order 1
        let k2 = f(t + h, &ye);
        let yhi: Vec<f64> = (0..m).map(|i| y[i] + h / 2.0 * (k1[i] + k2[i])).collect(); // Heun
        let mut ss = 0.0;
        for i in 0..m {
            let sc = atol + rtol * y[i].abs().max(yhi[i].abs());
            ss += ((yhi[i] - ye[i]) / sc).powi(2);
        }
        let err = (ss / m as f64).sqrt();
        if err <= 1.0 { // accept and record
            t += h;
            y = yhi;
            run.t.push(t); run.h.push(h); run.y.push(y.clone());
        } else { // reject: retry with smaller h
            run.nrej += 1;
        }
        h *= (0.9 * err.powf(-0.5)).clamp(0.2, 5.0);
    }
    run
}

def rk4_step(f, t, y, h):
    k1 = f(t, y)
    k2 = f(t + h / 2, y + h / 2 * k1)
    k3 = f(t + h / 2, y + h / 2 * k2)
    k4 = f(t + h, y + h * k3)
    return y + h / 6 * (k1 + 2 * k2 + 2 * k3 + k4)

def rk_solve(step, f, t0, y0, h, n):
    t = t0 + h * np.arange(n + 1)
    Y = np.zeros((n + 1, np.size(y0))); Y[0] = y0
    for i in range(n):
        Y[i + 1] = step(f, t[i], Y[i], h)
    return t, Y

impl System<f64, State> for Repressilator {
    fn system(&self, _t: f64, y: &State, dy: &mut State) {
        let rep = [y[5], y[3], y[4]]; // m1 repressed by p3, m2 by p1, m3 by p2
        for i in 0..3 {
            dy[i] = -y[i] + ALPHA / (1.0 + rep[i].powf(N)) + ALPHA0;
            dy[i + 3] = -BETA * (y[i + 3] - y[i]);
        }
    }

    k1  <- f(t, y); k2 <- f(t + h, y + h * k1)

}

// rust/examples/runge_kutta_c7.rs  —  cargo run --example runge_kutta_c7
// C7: events by hand: ode_solvers has no event location, so we bracket the sign
// change of g on the dense output and refine it by bisection
use ode_solvers::continuous_output_model::ContinuousOutputModel;
use ode_solvers::{Dopri5, System, Vector2, Vector3};

struct Sir;
impl System<f64, Vector3<f64>> for Sir {
    fn system(&self, _t: f64, y: &Vector3<f64>, dy: &mut Vector3<f64>) {
        let (beta, gamma, n) = (0.3, 0.1, 10000.0);
        let (s, i) = (y[0], y[1]);
        *dy = Vector3::new(-beta * s * i / n, beta * s * i / n - gamma * i, gamma * i);
    }
}
struct LotkaVolterra;
impl System<f64, Vector2<f64>> for LotkaVolterra {
    fn system(&self, _t: f64, y: &Vector2<f64>, dy: &mut Vector2<f64>) {
        let (a, b, c, d) = (1.0, 0.1, 0.075, 1.5);
        *dy = Vector2::new(a * y[0] - b * y[0] * y[1], c * y[0] * y[1] - d * y[1]);
    }
}

// first root of g(t) on [t0, t1]: scan with spacing dt, then bisect
fn first_root(g: &dyn Fn(f64) -> f64, t0: f64, t1: f64, dt: f64) -> Option<f64> {
    let mut lo = t0;
    while lo < t1 {
        let hi = (lo + dt).min(t1);
        if g(lo).signum() != g(hi).signum() {
            let (mut a, mut b) = (lo, hi);
            for _ in 0..60 {
                let m = 0.5 * (a + b);
                if g(a).signum() == g(m).signum() { a = m } else { b = m }
            }
            return Some(0.5 * (a + b));
        }
        lo = hi;
    }
    None
}

fn main() {
    // (a) SIR: the peak as an event, g = beta S / N - gamma
    let mut dense = ContinuousOutputModel::default();
    let mut s = Dopri5::new(Sir, 0.0, 160.0, 1.0, Vector3::new(9990.0, 10.0, 0.0), 1e-10, 1e-8);
    s.integrate_with_continuous_output_model(&mut dense).unwrap();
    let g = |t: f64| 0.3 * dense.evaluate(t).unwrap()[0] / 10000.0 - 0.1;
    let tp = first_root(&g, 0.0, 160.0, 0.1).unwrap();
    let y = dense.evaluate(tp).unwrap();
    println!("peak at t = {:.8}: S = {:.6}, I = {:.6}, R = {:.6}", tp, y[0], y[1], y[2]);

    // (b) predator-prey: first time the lynx exceed 20
    let mut dense = ContinuousOutputModel::default();
    let mut s = Dopri5::new(LotkaVolterra, 0.0, 15.0, 1.0, Vector2::new(10.0, 5.0), 1e-10, 1e-10);
    s.integrate_with_continuous_output_model(&mut dense).unwrap();
    let g = |t: f64| dense.evaluate(t).unwrap()[1] - 20.0;
    let t20 = first_root(&g, 0.0, 15.0, 0.1).unwrap();
    println!("lynx reach 20 at t = {:.8}, prey x = {:.6}", t20, dense.evaluate(t20).unwrap()[0]);

    // (c) only looking at t = 0, 2.5, ..., 15
    let ys: Vec<f64> = (0..7).map(|k| dense.evaluate(2.5 * k as f64).unwrap()[1]).collect();
    println!("{:.2?}", ys);
    println!("found with spacing 2.5: {:?}", first_root(&g, 0.0, 15.0, 2.5));
}
