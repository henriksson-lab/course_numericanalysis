Exercise: Fourier series and the FFT

Goal

By the end of this exercise you should be able to:

  • compute a small DFT by hand, both as a matrix–vector product and with one even/odd FFT split, and write down the trigonometric interpolant it defines,
  • read fft() output correctly: the normalisation, which index holds which frequency, and how to get amplitude, period and peak time of a rhythm,
  • explain why the FFT costs \(O(n\log n)\) and the matrix \(O(n^2)\), and when a library FFT is slow,
  • predict from the sampling interval which rhythms are resolved and which are aliased, and to which period,
  • recognise leakage and reduce it with a window,
  • filter a noisy trace in frequency space, and see (and fix) what goes wrong at the edges,
  • use the convolution theorem, and tell circular from linear convolution.

The running example is a simulated clock-controlled gene measured every 2 h for 48 h, plus a simulated luciferase trace. The by-hand part uses pen, paper and a calculator.

Background

\(n\) equispaced samples \(x_0, \dots, x_{n-1}\), taken every \(\Delta t\), over a record of length \(T = n\Delta t\).

Facts used below:

  1. DFT. \(X_k = \sum_{j=0}^{n-1} x_j\, w^{jk}\) with \(w = e^{-2\pi i/n}\), for \(k = 0, \dots, n-1\). Here \(e^{i\theta} = \cos\theta + i\sin\theta\), so \(|e^{i\theta}| = 1\). \(k\) counts cycles per record: period \(T/k\), frequency \(k/T\).
  2. Inverse. \(x_j = \frac1n \sum_k X_k\, w^{-jk}\). As a matrix: \(X = Fx\) with \(F_{jk} = w^{jk}\), and \(F^{-1} = \bar F^{T}/n\).
  3. Real data. \(X_{n-k} = \overline{X_k}\): only \(k = 0, \dots, n/2\) carry information.
  4. Trigonometric interpolant (\(n\) even): \(p(t) = a_0 + \sum_{k=1}^{n/2-1}\big[a_k\cos\tfrac{2\pi kt}{T} + b_k \sin\tfrac{2\pi kt}{T}\big] + a_{n/2}\cos\tfrac{\pi n t}{T}\) with \(a_0 = X_0/n\), \(a_k = 2\,\mathrm{Re}X_k/n\), \(b_k = -2\,\mathrm{Im}X_k/n\), \(a_{n/2} = X_{n/2}/n\). It passes through every sample.
  5. Reading a rhythm. For \(x_j = A\cos(2\pi k t_j/T - \theta)\): \(X_k = \tfrac{nA}{2}e^{-i\theta}\). Amplitude \(A = 2|X_k|/n\) (for \(0 < k < n/2\)); the peak is at \(t = \theta/(2\pi)\cdot T/k\) with \(\theta = -\arg X_k\).
  6. FFT. With \(E\), \(O\) the DFTs of the even and odd samples (length \(n/2\)): \(X_k = E_k + w^kO_k\) and \(X_{k+n/2} = E_k - w^kO_k\) for \(k < n/2\). Cost \(n\log_2 n\) instead of \(n^2\).
  7. Nyquist. Sampling every \(\Delta t\) resolves frequencies up to \(f_N = 1/(2\Delta t)\), i.e. periods down to \(2\Delta t\). A frequency \(f\) above \(f_N\) gives the same samples as its alias \(|f - m/\Delta t|\), for the whole number \(m\) that brings it into \([0, f_N]\).
  8. Convolution theorem. For circular convolution \((h * y)_j = \sum_m h_m\,y_{(j-m) \bmod n}\): \(\mathrm{DFT}(h*y)_k = H_kY_k\). For ordinary (linear) convolution, pad both with zeros to length at least \(n_y + n_h - 1\) first.

Conventions differ between languages. R’s fft and numpy’s np.fft.fft both compute \(X_k\) exactly as in fact 1 (no \(1/n\)). R indexes from 1, so \(X_k\) is X[k + 1]; Python and Rust index from 0, so \(X_k\) is X[k]. R’s inverse fft(X, inverse = TRUE) does not divide by \(n\); numpy’s np.fft.ifft does. Rust’s rustfft works in place on complex vectors and divides by nothing in either direction. scipy.fft has the same functions as np.fft (and next_fast_len).

// rust/examples/fourier_fft_background.rs  —  cargo run --example fourier_fft_background
// The circadian gene: fft, amplitude, peak time and the inverse (rustfft).
use rustfft::{num_complex::Complex, FftPlanner};

fn main() {
    let x = [7.81, 8.81, 9.05, 9.98, 9.40, 8.50, 8.15, 7.47, 6.87, 6.41, 7.15, 7.37,
             7.81, 8.09, 9.64, 9.49, 9.29, 9.03, 8.25, 7.43, 6.98, 6.73, 6.72, 6.65];
    let n = x.len();                     // 24 samples, every 2 h, T = 48 h
    let mut planner = FftPlanner::<f64>::new();
    // rustfft works in place on complex numbers: copy x into a complex buffer
    let mut xc: Vec<Complex<f64>> = x.iter().map(|&v| Complex::new(v, 0.0)).collect();
    planner.plan_fft_forward(n).process(&mut xc);   // unnormalised: xc[0] = sum(x)
    println!("{}", xc[0].re / n as f64); // mean
    let k = 2;                           // 2 cycles per 48 h = 24-h period
    println!("{}", 2.0 * xc[k].norm() / n as f64);  // amplitude (index k, 0-based)
    let peak = (-xc[k].arg() / (2.0 * std::f64::consts::PI) * 24.0).rem_euclid(24.0);
    println!("{}", peak);                // peak time (h)
    planner.plan_fft_inverse(n).process(&mut xc);   // inverse, also unnormalised
    let err = (0..n).map(|j| (xc[j].re / n as f64 - x[j]).abs()).fold(0.0, f64::max);
    println!("{:e}", err);
}

By hand

B1. A DFT of four samples. A gene is measured every 6 h for one day (\(n = 4\), \(T = 24\) h): \(x = (3, 1, 1, 3)\) at \(t = 0, 6, 12, 18\) h. (a) Write down \(F_4\) (use \(w = e^{-2\pi i/4} = -i\)) and compute \(X = F_4x\). (b) Check facts 1 and 3: is \(X_0\) the sum? Is \(X_3 = \overline{X_1}\)? (c) Compute \(a_0, a_1, b_1, a_2\) and write the trigonometric interpolant \(p(t)\). Check that \(p(6) = 1\). (d) What are the amplitude of the 24-h rhythm and the time of its peak? Use fact 5, then check by finding the maximum of \(p\). (e) Use fact 2 to recover \(x_1\) from \(X\).

B2. One FFT step. Same \(x = (3, 1, 1, 3)\). (a) Write down the even samples and the odd samples. Compute their 2-point DFTs \(E\) and \(O\) (for \(n = 2\), \(w = -1\), so the DFT of \((a, b)\) is \((a + b, a - b)\)). (b) Combine them with fact 6 into \(X_0, \dots, X_3\) and compare with B1. (c) Count complex multiplications: the matrix product for \(n = 4\) needs \(n^2 = 16\). How many does the FFT need for \(n = 4\)? (Count only multiplications by \(w^k\) with \(w^k \ne \pm 1\).) (d) Roughly how many operations do the matrix (\(n^2\)) and the FFT (\(n\log_2 n\)) need for \(n = 2^{10}\) and \(n = 2^{20}\)? If a computer does \(10^9\) per second, how long does each take for \(n = 2^{20}\)?

B3. Reading fft output. A gene is sampled every 2 h for 48 h (\(n = 24\)). In R, fft(x)[3] is 0-18i and fft(x)[1] is 192. (a) Which \(k\) is fft(x)[3]? What period? Which index holds it in Python? (b) What are the mean and the amplitude of this rhythm? (c) At what time does it peak? (d) What is fft(x)[23]? Which \(k\) is that? (e) A second gene has fft(x)[3] equal to -18+0i. Same amplitude? When does it peak?

B4. Nyquist and aliasing. (a) Sampling every 4 h: what is the Nyquist frequency, and the shortest period that is resolved? (b) For each true period, 24, 12, 8, 6, 4.8 and 4 h, say whether 4-h sampling resolves it. If not, compute the alias frequency (fact 7) and the period you would report. (c) Repeat (b) for 2-h sampling. (d) An 8-h rhythm sampled every 4 h (exactly at Nyquist): the samples are \(\cos(2\pi(4j - p)/8)\) for a peak at time \(p\). Write the samples for \(p = 0\) and \(p = 2\). What does this tell you about rhythms at exactly the Nyquist frequency? (e) A lab wants to detect 12-h rhythms. What is the largest sampling interval that is (in theory) enough? Why is that not a good design in practice?

B5. Convolution by hand. \(y = (1, 2, 3, 4)\), two-point average \(h = (\tfrac12, \tfrac12, 0, 0)\). (a) Compute the circular convolution \((h * y)_j = \tfrac12(y_j + y_{j-1})\), with \(y_{-1} = y_3\). Which entry is affected by wrap-around? (b) Compute \(Y = F_4y\) and \(H = F_4h\), multiply entrywise, and transform back with fact 2. Do you get (a)? (c) \(|H_k|\) is the gain of the filter at frequency \(k\). What does the two-point average do to \(k = 1\) and to \(k = 2\) (the Nyquist frequency)? (d) Write down the linear convolution of \(y\) with \((\tfrac12, \tfrac12)\) (length 5). How long must you pad \(y\) and \(h\) so that the circular convolution gives it?

B6. Resolution and record length. With a 48-h record, the DFT frequencies are \(k/48\) per hour. (a) Which \(k\) (not necessarily whole) do a 24-h and a 22-h rhythm have? Can a 48-h experiment tell them apart? (b) How long must the record be for the two to land on neighbouring bins, i.e. for \(1/22 - 1/24 \ge 1/T\)? (c) Does sampling every 1 h instead of every 2 h help? Does zero-padding the 48-h record to 480 h help?

Which periods are removed completely? Is a moving average a good low-pass filter?

Answer E1

Mean \(8.045\), amplitude \(1.465\), peak at \(6.45\) h, exactly the fft() results of the lecture (true values 1.5 and 6 h). Nyquist period \(2\Delta t = 4\) h (6 cycles per day); the bins are at periods \(48/k\): 48, 24, 16, 12, …, 4 h, spaced \(1/48\) per hour (0.5 per day). With 4-h sampling the bins keep the same spacing but stop at 8 h (Nyquist 3 per day): amplitude \(1.400\), peak \(6.35\) h. With 1-h sampling (new noise between the old times) the axis runs to 12 per day: \(1.433\), \(6.20\) h. With 96 h at 2 h the Nyquist frequency stays at 6 per day but the bins are twice as dense (\(96/k\), the 24-h bin is \(k = 4\)): \(1.529\), \(6.28\) h. \(\Delta t\) sets the highest frequency, the record length sets the spacing; all three designs estimate the 24-h rhythm about equally well, because it is slow and on the grid.

Answer E4

Samples \(0.97\) (the noise), smoothed \(0.41\) with 25 of 192 coefficients. Cut-off 2 h: \(0.75\); 4 h: \(0.55\); 12 h: \(0.37\); 24 h: \(0.24\); 48 h: \(1.07\). The smaller the band you keep, the less noise passes, until the band no longer contains the signal. 24 h is best here only because the truth is a pure 24-h cosine with a whole number of cycles; a real gene has harmonics (12 h, 8 h) and an ultradian component that such a filter would remove (try fast amplitude 1 with cut-off 8 h). At 48 h the cut-off is above the clock frequency: the rhythm itself is filtered out, and the smoothed curve is almost flat, worse than the raw data. The same bias–noise trade-off as in C6.

Hints

Hint 1 — DFT by hand (B1, B2, B5)

Powers of \(w = -i\): \(w^0 = 1\), \(w^1 = -i\), \(w^2 = -1\), \(w^3 = i\), \(w^4 = 1\), so \(F_{jk} = (-i)^{jk \bmod 4}\). Multiply out row by row; \(i \cdot i = -1\). For the inverse use \(w^{-1} = i\) and divide by 4. In B2, the 2-point DFTs need no multiplication at all, and the only twiddle factors for \(n = 4\) are \(w^0 = 1\) and \(w^1 = -i\).

Hint 2 — reading fft output (B3, C3)

\(k\) = index − 1 in R. Period \(= T/k\). Amplitude \(2|X_k|/n\); \(|a + bi| = \sqrt{a^2+b^2}\). \(\arg(-18i) = -\pi/2\), \(\arg(-18) = \pi\). The peak time is \(\theta/(2\pi)\) of a period, with \(\theta = -\arg X_k\); add a period if it is negative. In R: Mod, Arg, Re, Im, Conj; Python: np.abs, np.angle, .real, .imag, .conj(); Rust: z.norm(), z.arg(), z.re, z.im, z.conj() (from rustfft::num_complex).

Hint 3 — aliasing (B4, C4)

Work in cycles per hour. Sampling every 4 h: \(f_s = 1/\Delta t = 0.25\), \(f_N = 0.125\). A 6-h rhythm has \(f = 0.1667 > f_N\); subtract \(f_s\): \(|0.1667 - 0.25| = 0.0833\), i.e. period 12 h. If the result is still above \(f_N\), subtract \(f_s\) again.

Hint 4 — the DFT matrix and timing (C1, C2)

R: outer(j, j) gives all products \(jk\), and exp(-2i * pi * outer(j, j) / n) the matrix; system.time times an expression. Python: np.outer, time.perf_counter(). Rust: std::time::Instant; plan once with FftPlanner, then process a Vec<Complex<f64>> in place. For the recursion, x[seq(1, n, by = 2)] in R and x[0::2] in Python are the even samples.

Hint 5 — windows and zero-padding (C5)

Multiply the signal by the window before the FFT. R: pad with c(w * y, rep(0, N - n)); Python: np.fft.fft(w * y, N) pads for you; Rust: Vec::resize(N, 0.0). In the padded transform, index \(k\) means \(k\) cycles per padded length (\(N\Delta t\) = 1200 h).

Hint 6 — filtering (C6, C7)

The signed frequency of each entry is c(0:(n/2), -(n/2 - 1):-1) in R and np.fft.fftfreq(n, d=1/n) in Python; in Rust entry \(k > n/2\) has frequency \(n - k\). Take Re() / .real after the inverse. A straight-line trend: fitted(lm(y ~ t)) in R, np.polyval(np.polyfit(t, y, 1), t) in Python. R’s stats::filter computes moving averages directly.

// The DFT matrix F[j][k] = w^(jk), w = exp(-2 pi i / n)
fn dft_matrix(n: usize) -> Vec<Vec<Complex<f64>>> {
    (0..n).map(|j| (0..n).map(|k| {
        Complex::from_polar(1.0, -2.0 * PI * ((j * k) % n) as f64 / n as f64)
    }).collect()).collect()
}

fn matvec(f: &[Vec<Complex<f64>>], x: &[f64]) -> Vec<Complex<f64>> {

}

use rustfft::{num_complex::Complex, FftPlanner};
use std::f64::consts::PI;
use std::time::Instant;

fn my_fft(x: &[Complex<f64>]) -> Vec<Complex<f64>> {
    let n = x.len();
    if n == 1 {
        return x.to_vec();
    }
    let even: Vec<Complex<f64>> = x.iter().step_by(2).cloned().collect();          // 0, 2, 4, ...
    let odd: Vec<Complex<f64>> = x.iter().skip(1).step_by(2).cloned().collect();   // 1, 3, 5, ...
    let (e, o) = (my_fft(&even), my_fft(&odd));
    let mut out = vec![Complex::new(0.0, 0.0); n];
    for k in 0..n / 2 {
        let wo = Complex::from_polar(1.0, -2.0 * PI * k as f64 / n as f64) * o[k];
        out[k] = e[k] + wo;
        out[k + n / 2] = e[k] - wo;
    }
    out
}

fn trig_interp(x: &[f64], big_t: f64, tt: f64) -> f64 {
    let n = x.len();

    let mut p = xf[0].re + xf[n / 2].re * (PI * n as f64 * tt / big_t).cos();

    p

// C6: smoothing a noisy bioluminescence trace by low-pass filtering, raw and detrended.
// The random noise differs from R and Python, so the digits differ a little.
use rand::{rngs::StdRng, SeedableRng};
use rand_distr::{Distribution, Normal};
use rustfft::{num_complex::Complex, FftPlanner};
use std::f64::consts::PI;

fn lowpass(y: &[f64], kmax: usize) -> Vec<f64> {
    let n = y.len();
    let mut planner = FftPlanner::<f64>::new();
    let mut buf: Vec<Complex<f64>> = y.iter().map(|&v| Complex::new(v, 0.0)).collect();
    planner.plan_fft_forward(n).process(&mut buf);
    for k in 0..n {
        let signed = if k <= n / 2 { k } else { n - k };   // |frequency| of entry k
        if signed > kmax { buf[k] = Complex::new(0.0, 0.0); }
    }
    planner.plan_fft_inverse(n).process(&mut buf);         // unnormalised
    buf.iter().map(|z| z.re / n as f64).collect()
}

fn rms(e: &[f64]) -> f64 {
    (e.iter().map(|v| v * v).sum::<f64>() / e.len() as f64).sqrt()
}

fn main() {
    let n = 240;                                          // every 30 min for 5 days
    let t: Vec<f64> = (0..n).map(|j| 0.5 * j as f64).collect();
    let truth: Vec<f64> = t.iter().map(|&s| 20.0 + 60.0 * (-s / 40.0).exp()
        + 30.0 * (-s / 80.0).exp() * (2.0 * PI * (s - 4.0) / 24.0).cos()).collect();
    let mut rng = StdRng::seed_from_u64(3);
    let noise = Normal::new(0.0, 6.0).unwrap();
    let y: Vec<f64> = truth.iter().map(|&v| v + noise.sample(&mut rng)).collect();
    // straight-line fit by the textbook formulas for slope and intercept
    let (tm, ym) = (t.iter().sum::<f64>() / n as f64, y.iter().sum::<f64>() / n as f64);
    let slope = (0..n).map(|j| (t[j] - tm) * (y[j] - ym)).sum::<f64>()
        / t.iter().map(|&s| (s - tm).powi(2)).sum::<f64>();
    let trend: Vec<f64> = t.iter().map(|&s| ym + slope * (s - tm)).collect();
    let ends: Vec<usize> = (0..10).chain(n - 10..n).collect();   // first and last 5 h
    for kmax in [5, 10, 15, 20, 30, 60] {
        let s = lowpass(&y, kmax);
        let resid: Vec<f64> = (0..n).map(|j| y[j] - trend[j]).collect();
        let d: Vec<f64> = lowpass(&resid, kmax).iter().zip(&trend).map(|(a, b)| a + b).collect();
        let es: Vec<f64> = (0..n).map(|j| s[j] - truth[j]).collect();
        let ed: Vec<f64> = (0..n).map(|j| d[j] - truth[j]).collect();
        let pick = |e: &[f64]| ends.iter().map(|&j| e[j]).collect::<Vec<f64>>();
        println!("kmax {:2} (periods >= {:5.1} h): raw {:.2} (ends {:.2})  detrended {:.2} (ends {:.2})",
                 kmax, 120.0 / kmax as f64, rms(&es), rms(&pick(&es)), rms(&ed), rms(&pick(&ed)));
    }
    let e: Vec<f64> = (0..n).map(|j| y[j] - truth[j]).collect();
    println!("noise: {:.2}", rms(&e));
}

The three languages draw different random noise, so the digits differ; the pattern does not. (a) On the raw trace the error at the ends stays large (13 for \(k_\text{max} = 15\), twice the noise): the start (about 95) and end (about 20) do not match, and the filter rings. (b) After removing a straight line the ends are as good as the middle, and the overall error halves. (c) Around \(k_\text{max} = 10\)–\(15\) (periods down to 8–12 h): small \(k_\text{max}\) removes part of the signal (the decay at the start is fast), large \(k_\text{max}\) lets noise through (at \(k_\text{max} = 60\) the error rises again). This is the same bias–noise trade-off as for smoothing splines.

// rust/examples/fourier_fft_c7.rs  —  cargo run --example fourier_fft_c7
// C7: the convolution theorem: circular vs linear (zero-padded) convolution, and the
// gain of a moving-average filter.
use rustfft::{num_complex::Complex, FftPlanner};

fn fft(x: &[f64]) -> Vec<Complex<f64>> {
    let mut buf: Vec<Complex<f64>> = x.iter().map(|&v| Complex::new(v, 0.0)).collect();
    FftPlanner::<f64>::new().plan_fft_forward(x.len()).process(&mut buf);
    buf
}

// circular convolution of two real vectors of the same length, via the FFT
fn cconv(y: &[f64], h: &[f64]) -> Vec<f64> {
    let n = y.len();
    let mut prod: Vec<Complex<f64>> = fft(y).iter().zip(fft(h)).map(|(a, b)| a * b).collect();
    FftPlanner::<f64>::new().plan_fft_inverse(n).process(&mut prod);
    prod.iter().map(|z| z.re / n as f64).collect()
}

Where this leads

  • Numerical differentiation (Part 7): differentiating a sampled signal multiplies \(X_k\) by \(2\pi i k/T\), so it amplifies high-frequency noise; finite differences have the same problem, and smoothing first (C6) is a common remedy.
  • Numerical integration (Part 7): the trapezoid rule is extremely accurate for smooth periodic functions over a whole period, for the same reason trigonometric interpolation works well here.
  • The diffusion (heat) equation by finite differences (Part 10): each Fourier mode of a concentration profile decays at its own rate, and the stability limit of the explicit scheme is decided by the fastest (Nyquist) mode.
  • Deconvolution (the blur slide) is the ill-conditioned problem of The SVD, rank deficiency and regularisation in another basis: dividing by small \(|H_k|\) is dividing by small singular values.
