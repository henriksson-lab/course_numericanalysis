Exercise: random numbers and Monte Carlo

Goal

By the end of this exercise you should be able to:

  • explain why pseudo-random numbers are deterministic, run a toy generator by hand, and use seeds for reproducible simulations,
  • turn uniform numbers into draws from another distribution by inverse-transform and rejection sampling,
  • estimate an integral or a probability by Monte Carlo and report it with a standard error,
  • read the \(1/\sqrt{N}\) law off a log–log plot and plan \(N\) for a target accuracy,
  • recognise when the standard error cannot be trusted (infinite variance, rare events, bad importance weights),
  • explain the curse of dimensionality and when Monte Carlo beats a grid,
  • use importance sampling for a rare-event probability, and check it with the effective sample size,
  • test whether motif hits are enriched in promoters by simulation, and compare with the exact answer.

The by-hand part uses pen, paper and a pocket calculator (for log and exp). The code part checks your hand answers and then works at sizes where only code works.

Background

Facts used below:

  1. Pseudo-random generators. A generator computes a long sequence of numbers from a seed by a fixed rule. A linear congruential generator (LCG) is \(x_{n+1} = (a x_n + c) \bmod m\), \(u_n = x_n/m\). The same seed gives the same sequence; the sequence repeats after at most \(m\) steps. Default generators: R, Mersenne Twister (set.seed); numpy, PCG64 (np.random.default_rng); Rust, StdRng = ChaCha12 (rand). The three give different streams for the same seed.
  2. Inverse transform. If \(U \sim \text{Uniform}(0,1)\) and \(F\) is a CDF, then \(X = F^{-1}(U)\) has CDF \(F\). Exponential with rate \(\lambda\): \(X = -\log(1 - U)/\lambda\) (or \(-\log(U)/\lambda\), since \(1-U\) is uniform too). Discrete: cut \([0, 1)\) at the cumulative probabilities and see where \(U\) falls.
  3. Rejection. To draw from a density \(f\) using a proposal \(g\) with \(f \le M g\): draw \(x \sim g\) and \(v \sim \text{Uniform}(0,1)\); keep \(x\) if \(v < f(x)/(M g(x))\). The acceptance rate is \(1/M\).
  4. Monte Carlo integration. \(\int_a^b f(x)\,dx = (b-a)\,\mathrm{E}[f(U)]\) with \(U \sim \text{Uniform}(a,b)\). With \(y_i = (b-a) f(U_i)\): \[\hat I = \bar y, \qquad \text{SE} = \frac{s}{\sqrt N}, \quad s = \text{sample sd of the } y_i.\] Report \(\hat I \pm 2\,\text{SE}\). A probability is the integral of an indicator: \(\hat p = k/N\), \(\text{SE} = \sqrt{\hat p(1-\hat p)/N}\).
  5. Error rate. The Monte Carlo error falls like \(N^{-1/2}\) in any dimension, if the variance of \(f(U)\) is finite. A grid rule of order \(p\) with \(N\) points in \(d\) dimensions has error about \(N^{-p/d}\).
  6. Importance sampling. \(\int h(x) f(x)\,dx = \mathrm{E}_g[h(X)\,w(X)]\), \(w = f/g\), \(X \sim g\). The proposal \(g\) must be positive wherever \(h f \neq 0\) and should have heavier tails than \(|h| f\). Effective sample size \(\text{ESS} = (\sum w_i)^2 / \sum w_i^2\).

// Background: a seeded generator, uniform numbers, and a Monte Carlo mean with its SE.
use rand::{rngs::StdRng, RngExt, SeedableRng};

fn main() {
    let mut rng = StdRng::seed_from_u64(42); // fix the stream
    let u: Vec<f64> = (0..5).map(|_| rng.random::<f64>()).collect(); // uniform in [0, 1)
    let rounded: Vec<f64> = u.iter().map(|v| (v * 1e4).round() / 1e4).collect();
    println!("{:?}", rounded);

    let n = 10000;
    let fx: Vec<f64> = (0..n).map(|_| rng.random::<f64>().powi(2)).collect(); // f(U), f(x) = x^2
    let mean = fx.iter().sum::<f64>() / n as f64;
    let var = fx.iter().map(|v| (v - mean).powi(2)).sum::<f64>() / (n - 1) as f64;
    println!("{} {}", mean, (var / n as f64).sqrt()); // exact: 1/3
}

Rust prints numbers in its own format (e.g. 2.8665157188630015e-7 rather than 2.866516e-07). In Rust, rng.random::<f64>() and numpy’s rng.random() return numbers in \([0, 1)\), which can be 0; R’s runif never returns 0 or 1. That is why the Python and Rust code below use 1 - U inside a log.

By hand

B1. A toy generator. Use the LCG \(x_{n+1} = (5x_n + 1) \bmod 16\). (a) Starting from the seed \(x_1 = 1\), compute \(x_2, \dots, x_8\) and the corresponding \(u_n = x_n/16\). (b) Continue until the sequence repeats. What is the period? Which values of \(x\) appear? (c) Start instead from the seed 7. Where does this sequence join the one from (a)? (d) Change the multiplier to \(a = 4\) (seed 1). What happens? And with \(a = 3\), \(c = 0\) (seed 1)? (e) Someone reruns your simulation without setting the seed and gets a slightly different answer. Someone else reruns it with your seed in Python instead of R and also gets a different answer. Which of the two is a problem?

B2. Inverse transform. Waiting times between transcriptional bursts are exponential with rate \(\lambda = 0.5\) per hour. (a) Solve \(u = F(x) = 1 - e^{-\lambda x}\) for \(x\). (b) Turn the uniform numbers \(u = 0.3\), \(0.75\) and \(0.95\) into waiting times. (Useful: \(\ln 0.7 = -0.357\), \(\ln 0.25 = -1.386\), \(\ln 0.05 = -2.996\).) (c) Which \(u\) gives the median waiting time, and what is it? (d) A genome has base composition A 0.3, C 0.2, G 0.2, T 0.3. Write down the cut points in \([0, 1)\) and give the base for \(u = 0.45\), \(0.95\) and \(0.3\).

B3. Rejection sampling. Target: the Beta(2, 4) density \(f(x) = 20x(1-x)^3\) on \([0, 1]\); proposal: Uniform(0, 1). (a) Find the maximum of \(f\) (set \(f'(x) = 0\)). What is the smallest \(M\) you can use, and the acceptance rate? (b) For the pairs \((x, v) = (0.25, 0.9)\), \((0.8, 0.1)\), \((0.5, 0.5)\), decide whether \(x\) is accepted. (c) On average, how many proposals are needed for 1000 accepted draws? (d) What goes wrong if you take \(M = 1.5\) by mistake? Would the code warn you?

B4. Monte Carlo by hand. Estimate \(\int_0^1 x^2\,dx\) from the four uniform numbers \(0.1, 0.4, 0.7, 0.9\). (a) Compute the estimate, the sample sd \(s\) (divide by \(N-1\)) and the standard error. Is the true value \(1/3\) within \(\pm 2\) SE? (b) The true sd of \(U^2\) is \(\sqrt{1/5 - 1/9} = 0.298\). How many draws do you need for an SE of 0.001? (c) You have \(N = 10\,000\) and want the error 10 times smaller. How many draws do you need? And for the trapezoid rule (error \(\propto N^{-2}\))?

B5. The curse of dimensionality. (a) A grid with 10 points per axis: how many function evaluations in \(d = 1, 3, 6, 10\) dimensions? At 1 µs per evaluation, how long does each take? (b) With a budget of \(N = 10^6\) evaluations, how many grid points per axis can you afford in \(d = 2\), \(d = 6\) and \(d = 10\)? (c) A rule of order \(p\) has error \(\approx N^{-p/d}\); Monte Carlo has error \(\approx N^{-1/2}\). In which dimension do the two rates match for the trapezoid rule (\(p = 2\))? For Simpson’s rule (\(p = 4\))?

B6. Motif hits in promoters, exactly. A 1 Mb region (\(G = 10^6\) bp) has 50 non-overlapping promoters of 1000 bp, none at the ends. A motif hit is \(L = 10\) bp long; its start position is uniform on \(1, \dots, G - L + 1\). (a) For which start positions \(s\) does a hit overlap the promoter \([p, p + 999]\)? Compute the probability \(p_\text{hit}\) that one random hit overlaps any promoter. (b) With 200 independent hits, the number \(K\) of overlapping hits is Binomial\((200, p_\text{hit})\). Compute \(\mathrm{E}[K]\) and \(\mathrm{sd}(K)\). How many sd above the mean is the observed \(k = 18\)? (c) A simulation with \(B = 10\,000\) random placements found 122 with \(K \ge 18\). Give the simulated p-value, its SE, and the \((k+1)/(B+1)\) version. How large must \(B\) be for an SE of 10% of the p-value? (d) Name two features of real genomes that make the uniform, independent placement unrealistic. Why does that favour simulation over a formula?

B7. A rare event. A standardised motif score \(X\) of a random sequence is approximately \(N(0, 1)\); \(P(X > 5) = 2.87 \times 10^{-7}\). (a) With \(N = 10^5\) plain Monte Carlo draws, how many draws above 5 do you expect? What is the probability of seeing none? What do the estimate and its SE then say? (b) Importance sampling with proposal \(g = N(5, 1)\). Show that \(w(x) = \phi(x)/\phi(x - 5) = e^{12.5 - 5x}\), where \(\phi\) is the standard normal density. Evaluate \(w\) at \(x = 5\), \(5.5\), \(6\). (c) Four proposal draws are \(4.2, 5.1, 5.6, 6.3\). Compute \(h(x_i) w(x_i)\) with \(h(x) = 1\) if \(x > 5\), else 0, and the estimate. (Useful: \(e^{-13} = 2.26\times10^{-6}\), \(e^{-15.5} = 1.86\times10^{-7}\), \(e^{-19} = 5.6\times10^{-9}\).) (d) What fraction of the proposal draws fall above 5? Why does that help?

In code

C1. Generators and seeds. (a) Write lcg(n, seed, a, c, m) and check B1 (a), (b) and (d). (b) Implement RANDU: \(x_{n+1} = 65539\,x_n \bmod 2^{31}\), seed 1, \(u_n = x_n/2^{31}\). Draw 30 000 numbers and count the distinct values of \(9u_n - 6u_{n+1} + u_{n+2}\), rounded to 3 decimals. Do the same with your language’s default generator. What do you conclude? (c) Draw three uniforms twice with the same seed and check that they are identical. Compare the three numbers with those of a classmate who uses another language.

C2. Inverse-transform sampling. (a) Draw \(10^5\) burst waiting times with \(\lambda = 0.5\) per hour by inverse transform. Check the mean and sd (both \(1/\lambda = 2\)) and the fraction of waits longer than 6 h against \(e^{-3}\). (b) Draw \(10^5\) bases with the composition of B2(d) using the cumulative probabilities (findInterval; Python np.searchsorted). Check the frequencies.

C3. Rejection sampling. Write a rejection sampler for the Beta(2, 4) density of B3 with a uniform proposal. (a) With \(M = f(1/4)\) and with \(M = 10\): compare the acceptance rate with \(1/M\) and the mean of the accepted draws with \(1/3\). (b) Run it with \(M = 1.5\). What is the mean now? Compare with B3(d).

C4. Monte Carlo integration with an error bar. The OD curve \(N(t) = K/(1 + (K/N_0 - 1)e^{-rt})\), \(K = 1.2\), \(N_0 = 0.05\), \(r = 0.8\) per hour (the running example), has exact area \(\int_0^{10} N\,dt = \tfrac{K}{r}\log\frac{e^{10r} + K/N_0 - 1}{K/N_0} = 7.2444\). (a) Estimate the area from \(N = 1000\) uniform times, with SE and a \(\pm 2\) SE interval. Does it contain the exact value? (b) For \(N = 10^2, \dots, 10^5\), compute the root-mean-square error over 20 repeats, and the slope of \(\log(\text{RMS})\) against \(\log N\) (the lecture plots the same on log–log axes). (c) From the sample sd in (a), how many draws do you need for \(2\,\text{SE} = 0.01\)?

C5. When the error bar lies. Estimate \(\int_0^1 x^{-3/4}\,dx = 4\) and \(\int_0^1 x^{-1/4}\,dx = 4/3\) with \(N = 10^5\) draws, for seeds 1 to 5. Print each estimate with its SE. (a) For which integrand do the SEs agree between seeds, and is the truth within \(\pm 2\) SE? (b) Compute \(\int_0^1 (x^{-3/4})^2\,dx\) and \(\int_0^1 (x^{-1/4})^2\,dx\) by hand. What explains (a)?

C6. The curse of dimensionality. Toy marginal likelihood: \(d\) parameters with prior \(N(0, 1)\), one measurement \(y_i = 1\) each with noise sd 1, so \(Z = \phi(1; 0, \sqrt2)^d\) exactly. With a budget of \(10^5\) likelihood evaluations: (a) Grid: \(n = \lfloor 10^{5/d} \rfloor\) points per axis at the prior quantiles \(\Phi^{-1}((i - 0.5)/n)\), \(i = 1..n\) (qnorm; Python scipy.stats.norm.ppf), all \(n^d\) combinations, $Z = $ mean likelihood. (b) Monte Carlo: the same number \(n^d\) of draws from the prior. For \(d = 1, 2, 3, 4, 6, 8, 10\) print \(n\), \(n^d\), the relative errors of both, and the relative SE of Monte Carlo. Where is the crossover? Compare with B5(c). Compute the likelihood on the log scale and sum over parameters before exp.

C7. Motif hits in promoters, simulated. Set up the region of B6 (promoters start at \(10001, 30001, \dots\), every 20 000 bp). (a) Simulate \(B = 10\,000\) placements of 200 hits and count the overlaps each time. Compare the mean and variance of the counts with the binomial values. (b) Give the simulated p-value for \(k_\text{obs} = 18\) with SE and the \((k+1)/(B+1)\) version, and the exact value (pbinom; Python scipy.stats.binom.sf). (c) Repeat for \(k_\text{obs} = 25\). How reliable is the simulated p-value now?

C8. Importance sampling. (a) Estimate \(P(X > 5)\), \(X \sim N(0,1)\), with \(10^5\) plain draws and compare with the exact value (pnorm(5, lower.tail = FALSE); Python norm.sf(5)). (b) Use importance sampling with proposals \(N(3, 1)\), \(N(5, 1)\) and \(N(7, 1)\). Report each estimate with its relative SE. Which proposal is best, and why? (c) Failure: estimate \(\int \phi(x)\,dx = 1\) with \(w = \phi(x)/g(x)\) for proposals \(g = N(0, s^2)\) with \(s = 0.5, 1, 2, 5\). Print the estimate, SE, ESS and the largest weight’s share of the total. Which proposal is dangerous, and which number tells you?

E1. (the \(1/\sqrt N\) law) With OD-curve area, click +100 and write down the estimate, the SE and the error. Click +10 000 (\(N = 10\,100\)) and then +100 000 (\(N = 110\,100\)) and do the same. By what factor does the SE shrink per factor 100 in \(N\)? In panel (b), how do the error dots relate to the dashed line, and why do they scatter around it?

Answer E1

\(N = 100\): \(6.929 \pm 0.85\), SE \(0.426\), error \(-0.32\) (4.3 %). \(N = 10\,100\): \(7.230 \pm 0.083\), SE \(0.0415\), error \(-0.015\) (0.20 %). \(N = 110\,100\): \(7.232 \pm 0.025\), SE \(0.0125\), error \(-0.013\) (0.18 %). From \(N = 100\) to \(10\,100\) the SE falls by \(0.426/0.0415 = 10.3 \approx \sqrt{101}\): 100 times more draws for one more digit. The dots in panel (b) follow the dashed line \(\sigma/\sqrt N\) (\(\sigma = 4.16\)) with slope \(-\tfrac12\), but the actual error is random: whenever the running mean crosses the exact value the error dips far below the line, and it rarely stays far above it. At \(N = 10\,100\) the error is a third of an SE, at \(N = 110\,100\) about one SE, so it barely changed while the SE fell threefold. The SE describes the typical size of the error, not the error of one run.

E2. (is the error bar honest?) Stay with the OD-curve area. For seeds 1 to 10, move the seed slider and click +1000 once each time. Note the estimate and whether the exact value is inside \(\pm 2\) SE. How often does the band miss, and how often should it?

Answer E2

All ten SEs are about \(0.13\) (\(4.16/\sqrt{1000} = 0.132\)), so the band is \(\pm 0.26\) or \(\pm 0.27\) every time. The estimates are 7.141, 7.242, 7.320, 7.485, 6.989, 7.200, 7.554, 7.242, 7.287, 7.285. Only seed 7 misses: \(7.554 \pm 0.26\) ends at \(7.29\), just above the exact \(7.244\) (seeds 4 and 5 are close to the edge). A \(\pm 2\) SE band is a 95 % interval, so about 1 run in 20 should miss; 1 in 10 is within chance. This is why a single seed that “looks good” proves nothing, and why the SE, not the agreement of one run with a known answer, is what you report.

E3. (the motif test) Click motif overlap P(K ≥ 18), then +10 000. Compare the simulated p-value, its SE and the number of placements with \(K \ge 18\) with the lecture (122 of 10 000 in R) and with the exact \(0.01314\). What is the relative SE, and how many placements would you need for 10 % relative SE? Click +100 000 and check.

Answer E3

\(N = 10\,000\): 143 placements with \(K \ge 18\), estimate \(0.0143 \pm 0.0024\), SE \(0.00119\), error \(0.0012\) (8.8 %); the exact value is inside the band. R’s 122 and the demo’s 143 differ by \(0.0021\), less than 2 SE: two different streams, both honest. The relative SE is \(0.00119/0.0143 \approx 8\%\). For 10 % you need \(B \approx 100/p \approx 7\,600\) placements (B6c), so \(10\,000\) is already enough. At \(N = 110\,000\): 1 482 hits, \(0.01347 \pm 0.00070\), SE \(3.48\times10^{-4}\) (2.6 %): 11 times more draws, \(\sqrt{11} = 3.3\) times smaller SE.

E4. (rare event and importance sampling) Click rare event P(X > 5) with importance sampling off, then +100 000. What do the estimate, the SE and the readout say? Where are the error dots in panel (b), and where is the dashed line? Now tick importance sampling (this restarts the run), click +1000, then +100 000 (\(N = 101\,000\)). Read the estimate, the relative SE and the number of draws above 5.

Answer E4

Plain: 0 draws above 5, estimate \(0 \pm 0\), SE 0, error 100 %; the readout warns that SE = 0 claims certainty. In panel (b) the error is stuck at 1 (100 %) for every \(N\), and the dashed true SE \(\sqrt{p(1-p)}/(p\sqrt N)\) lies above it (5.9 at \(N = 10^5\)): the true uncertainty is larger than the answer, but the sample cannot show it. With importance sampling: at \(N = 1000\), 509 draws above 5 and \(2.69\times10^{-7} \pm 4.1\times10^{-8}\) (SE 7.7 %); at \(N = 101\,000\), 50 582 draws above 5 and \(2.878\times10^{-7} \pm 4.3\times10^{-9}\), relative SE \(0.75\%\), error \(0.39\%\), as in the lecture. The relative sd of one draw drops from \(\sqrt{(1-p)/p} = 1868\) to \(2.38\): the variance falls by a factor \((1868/2.38)^2 \approx 6\times10^5\), so plain Monte Carlo would need about 600 000 times more draws for the same SE.

E5. (the curse of dimensionality) Open Curse of dimensionality (budget \(10^5\), seed 1). Move \(d\) from 1 to 10 and read the grid error, the expected Monte Carlo SE and the error of the Monte Carlo run. Where does Monte Carlo start to win? Then read panel (d) and the second readout line at \(d = 10\) and \(d = 20\): how many evaluations does each method need for 1 % error, and how long is that at 1 µs per evaluation?

Answer E5

Grid errors: \(< 10^{-8}\) (\(d = 1\)), 0.016 % (\(d = 2\)), 0.49 % (\(d = 3\)), 2.8 % (\(d = 4\)), 18 % (\(d = 6\)), 78 % (\(d = 10\), 3 points per axis), the numbers of C6. The expected Monte Carlo SE grows only slowly: 0.19 %, 0.29 %, 0.39 %, 0.50 %, 0.74 %, 1.5 %; the seed-1 run has error 1.2 % at \(d = 10\). The grid wins at \(d = 1, 2\), the two are level at \(d = 3\), and Monte Carlo wins from \(d = 4\), as B5(c) predicted for a second-order rule. For 1 % at \(d = 10\) the grid needs 65 points per axis, about \(10^{18}\) evaluations (43 000 years), Monte Carlo 213 110 draws (0.2 s). At \(d = 20\): grid 101 per axis, \(10^{40}\) evaluations (far beyond the age of the universe); Monte Carlo about 5 million draws (5 s). Monte Carlo’s cost also grows with \(d\), like \(1.364^d\), because the likelihood becomes more peaked relative to the prior, but exponentially more slowly than the grid’s.

Hints

Hint 1 — random numbers and seeds (B1, C1)

%% in R and % in Python and Rust are “mod” (the remainder after division). In R: set.seed, runif, identical. In Python: rng = np.random.default_rng(seed), then rng.random(n), rng.integers, rng.normal. In Rust: StdRng::seed_from_u64(seed) and rng.random::<f64>() from rand, normal draws with rand_distr::StandardNormal. For RANDU, \(65539 x\) stays below \(2^{53}\), so doubles (R) are exact; Python integers are always exact.

Hint 2 — inverse transform and rejection (B2, B3, C2, C3)

Set \(u = F(x)\) and solve for \(x\): take logs. The cut points for the bases are \(0, 0.3, 0.5, 0.7, 1\); a \(u\) exactly on a cut point goes to the interval that starts there. For rejection, \(f'(x) = 20(1-x)^2(1 - 4x)\). Compare R’s rexp and sample (with prob =); Python rng.exponential(scale = 1/lam) and rng.choice(bases, p = prob).

Hint 3 — standard errors and planning N (B4, C4)

SE \(= s/\sqrt N\), so to make the SE \(c\) times smaller you need \(c^2\) times more draws. To reach a target SE \(\delta\): \(N = (s/\delta)^2\). Sample sd: R sd (divides by \(N-1\)), Python x.std(ddof=1) (numpy’s default ddof=0 divides by \(N\)). For the slope: R coef(lm(log(rms) ~ log(N))), Python np.polyfit(np.log(N), np.log(rms), 1). Repeat runs with replicate in R or a list comprehension in Python.

Hint 4 — the curse of dimensionality (B5, C6)

\(N^{-p/d} = N^{-1/2}\) when \(p/d = 1/2\). For the grid in R: expand.grid(rep(list(nodes), d)) builds all combinations; in Python itertools.product(nodes, repeat=d); in Rust, write grid point \(k\) in base \(n\): its \(j\)-th digit is the index of the node on axis \(j\). Store parameters as a \(d \times N\) matrix and use colSums(dnorm(y, th, 1, log = TRUE)) (Python norm.logpdf(...).sum(axis=0)), so the product of \(d\) small numbers does not underflow.

Hint 5 — motif hits (B6, C7)

A hit \([s, s + 9]\) overlaps \([p, p + 999]\) when \(s + 9 \ge p\) and \(s \le p + 999\). To test many hits at once against sorted, non-overlapping promoters: find the last promoter that starts at or before the hit’s end (R findInterval; Python np.searchsorted(pstart, s + L - 1, side="right"); Rust pstart.partition_point(|&p| p <= s + L - 1)), then check that it has not ended before the hit starts. Draw starts with sample.int(G - L + 1, n, replace = TRUE) (Python rng.integers(1, G - L + 2, n); the upper end is excluded). pbinom(k - 1, n, p, lower.tail = FALSE) is \(P(K \ge k)\); in statrs, Binomial::sf(k - 1).

Hint 6 — importance sampling (B7, C8)

\(\phi(x) = e^{-x^2/2}/\sqrt{2\pi}\), so \(\phi(x)/\phi(x - 5) = \exp\!\big(-\tfrac{x^2}{2} + \tfrac{(x-5)^2}{2}\big)\); expand the square. In R, dnorm(x, mean, sd) and pnorm; in Python, scipy.stats.norm.pdf and norm.sf; in Rust, write the density yourself and use statrs::distribution::Normal for sf. The ESS is between 1 (one weight dominates) and \(N\) (all weights equal).

use rand::{rngs::StdRng, RngExt, SeedableRng};

fn main() {
    let mut rng = StdRng::seed_from_u64(1);
    let lambda = 0.5;
    let n = 100000;
    // random::<f64>() is in [0, 1): use 1 - U so the log never sees 0
    let x: Vec<f64> = (0..n).map(|_| -(1.0 - rng.random::<f64>()).ln() / lambda).collect();
    let mean = x.iter().sum::<f64>() / n as f64;
    let sd = (x.iter().map(|v| (v - mean).powi(2)).sum::<f64>() / (n - 1) as f64).sqrt();
    let p6 = x.iter().filter(|&&v| v > 6.0).count() as f64 / n as f64;
    println!("{} {} {} {}", mean, sd, p6, (-lambda * 6.0).exp());

    let bases = ['A', 'C', 'G', 'T'];
    let cum = [0.3, 0.5, 0.7, 1.0]; // cumulative probabilities
    let mut counts = [0usize; 4];
    for _ in 0..n {
        let u = rng.random::<f64>();
        let k = cum.partition_point(|&c| c <= u); // first k with cum[k] > u
        counts[k] += 1;
    }
    for k in 0..4 {
        println!("{} {:.3}", bases[k], counts[k] as f64 / n as f64);
    }
}

// C3: rejection sampling from Beta(2, 4) with a uniform proposal.
use rand::{rngs::StdRng, RngExt, SeedableRng};

fn f(x: f64) -> f64 {
    20.0 * x * (1.0 - x).powi(3)
}

// returns (acceptance rate, accepted draws)
fn rejection(n: usize, m: f64, rng: &mut StdRng) -> (f64, Vec<f64>) {
    let mut acc = Vec::new();
    for _ in 0..n {
        let x = rng.random::<f64>();
        if rng.random::<f64>() < f(x) / m {
            acc.push(x);
        }
    }
    (acc.len() as f64 / n as f64, acc)
}

fn mean(v: &[f64]) -> f64 {
    v.iter().sum::<f64>() / v.len() as f64
}

fn main() {
    let mut rng = StdRng::seed_from_u64(1);
    for m in [f(0.25), 10.0] {
        let (rate, x) = rejection(100000, m, &mut rng);
        println!("M = {:6.3}  acceptance {:.4}  (1/M = {:.4})  mean {:.4}", m, rate, 1.0 / m, mean(&x));
    }
    let (_, x) = rejection(100000, 1.5, &mut rng); // M too small
    println!("{}", mean(&x));
}

fn log_dnorm(x: f64, mu: f64, sd: f64) -> f64 {
    -0.5 * ((x - mu) / sd).powi(2) - sd.ln() - 0.5 * (2.0 * std::f64::consts::PI).ln()

}

// rust/examples/monte_carlo_c8.rs  —  cargo run --release --example monte_carlo_c8
// C8: importance sampling for a rare event, and a proposal that is too narrow.
use rand::{rngs::StdRng, RngExt, SeedableRng};
use rand_distr::StandardNormal;
use statrs::distribution::{ContinuousCDF, Normal};

fn dnorm(x: f64, mu: f64, sd: f64) -> f64 {
    (-0.5 * ((x - mu) / sd).powi(2)).exp() / (sd * (2.0 * std::f64::consts::PI).sqrt())
}

fn mean_sd(v: &[f64]) -> (f64, f64) {
    let n = v.len() as f64;
    let m = v.iter().sum::<f64>() / n;
    (m, (v.iter().map(|x| (x - m).powi(2)).sum::<f64>() / (n - 1.0)).sqrt())
}

fn main() {
    let n = 100000;
    let sqn = (n as f64).sqrt();
    let mut rng = StdRng::seed_from_u64(1);
    let mut z = || -> f64 { rng.sample(StandardNormal) };
    let hits = (0..n).filter(|_| z() > 5.0).count();
    println!("{} {:e}", hits as f64 / n as f64, Normal::new(0.0, 1.0).unwrap().sf(5.0));
    for mu in [3.0, 5.0, 7.0] {
        let hw: Vec<f64> = (0..n).map(|_| {
            let x = mu + z();
            if x > 5.0 { dnorm(x, 0.0, 1.0) / dnorm(x, mu, 1.0) } else { 0.0 }
        }).collect();
        let (m, s) = mean_sd(&hw);
        println!("proposal N({}, 1): estimate {:.4e}  relative se {:.4}", mu, m, s / sqn / m);
    }
    for sd in [0.5, 1.0, 2.0, 5.0] {
        let w: Vec<f64> = (0..n).map(|_| { let x = sd * z(); dnorm(x, 0.0, 1.0) / dnorm(x, 0.0, sd) }).collect();
        let (m, s) = mean_sd(&w);
        let sum: f64 = w.iter().sum();
        let ess = sum * sum / w.iter().map(|x| x * x).sum::<f64>();
        let maxw = w.iter().cloned().fold(0.0, f64::max);
        println!("proposal sd {:.1}: estimate {:.4}  se {:.4}  ESS {:6.0}  max share {:.5}",
                 sd, m, s / sqn, ess, maxw / sum);
    }
}

Where this leads

  • Stochastic simulation (Part 8): Gillespie’s algorithm draws exponential waiting times by inverse transform (C2) and chooses the next reaction by the discrete inverse transform of B2(d). Averages over simulated cells are Monte Carlo estimates with standard errors.
  • Identifiability and uncertainty of fitted parameters (Part 9): the bootstrap and profile likelihoods give uncertainty for fitted parameters; the bootstrap is again a Monte Carlo average.
