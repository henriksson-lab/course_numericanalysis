Exercise: convergence and cost

Goal

By the end of this exercise you should be able to:

  • separate truncation error (from the formula) and rounding error (from floating point) in a numerical derivative, and predict the step \(h\) where their sum is smallest,
  • read the order of accuracy \(p\) in error \(\approx C h^p\) from a table or from the slope of a log–log plot, and check it without knowing the exact answer,
  • tell linear from quadratic convergence of an iteration by the digits gained per step,
  • count operations for vector and matrix computations and use big-O to predict how the run time grows,
  • run a doubling experiment, read the cost exponent from a log–log plot of time against \(n\), and extrapolate to a full single-cell data set,
  • estimate the memory of a matrix (8 bytes per double) and say when sparse storage saves you.

Do the pen-and-paper problems first. The code problems measure the same things at sizes where only code works.

Background

Truncation vs rounding. The forward difference \(D(h) = \dfrac{f(t+h) - f(t)}{h}\) approximates \(f'(t)\). Taylor’s theorem gives

\[D(h) = f'(t) + \tfrac{h}{2} f''(\xi), \qquad \text{so the truncation error} \approx \tfrac{|f''|}{2}\,h.\]

Each value of \(f\) is stored with a relative error up to \(\varepsilon \approx 2.2\times10^{-16}\); the subtraction keeps that absolute error and the division by \(h\) amplifies it:

\[\text{rounding error} \approx \frac{\varepsilon\,|f(t)|}{h}.\]

The total error is V-shaped on a log–log plot, with its minimum near \(h \approx \sqrt{\varepsilon} \approx 10^{-8}\) for the forward difference.

Order of accuracy. A method has order \(p\) if its error \(\approx C h^p\), written \(O(h^p)\). On a log–log plot, \(\log_{10}\text{err} = \log_{10}C + p\log_{10}h\): a straight line with slope \(p\). From two points: \(p = \dfrac{\log_{10}(\text{err}_1/\text{err}_2)}{\log_{10}(h_1/h_2)}\). Without the exact answer: \(\dfrac{D(h) - D(h/2)}{D(h/2) - D(h/4)} \approx 2^p\).

Convergence of iterations. Linear: \(e_{k+1} \approx c\,e_k\) (\(0 < c < 1\)), a fixed \(-\log_{10}c\) digits per step. Quadratic: \(e_{k+1} \approx C e_k^2\), the number of correct digits roughly doubles each step.

Cost. For vectors of length \(n\) and \(n\times n\) matrices: dot product \(\approx 2n\) operations, matrix–vector \(\approx 2n^2\), matrix–matrix \(\approx 2n^3\). A cost \(O(n^p)\) is multiplied by \(2^p\) when \(n\) doubles. Time it at several \(n\) and fit the slope of \(\log(\text{time})\) against \(\log n\).

Memory. One double = 8 bytes. A dense \(r \times c\) matrix takes \(8rc\) bytes. A sparse matrix (compressed sparse column) stores about 12 bytes per non-zero: 8 for the value, 4 for its row index.

By hand

B1. (two difference formulas) (a) For \(f(x) = x^2\) at \(x = 1\) (true derivative \(2\)), compute the forward difference \(\dfrac{f(1+h) - f(1)}{h}\) for \(h = 0.1\) and \(h = 0.01\), and the errors. Show that the error is exactly \(h\), and connect this to \(\tfrac{h}{2}f''\). (b) Compute the central difference \(\dfrac{f(1+h) - f(1-h)}{2h}\) for \(h = 0.1\). What is its error? (c) Repeat (a) and (b) for \(f(x) = x^3\) at \(x = 1\) (true derivative \(3\)). Expand \((1 \pm h)^3\) to get each error as a polynomial in \(h\). What happens to each error when \(h\) is divided by 10? What are the two orders?

B2. (reading the order from a table) Three methods, three error tables:

\(h\) method A method B method C
\(0.2\) \(4.0\times10^{-3}\) \(8.0\times10^{-2}\)
\(0.1\) \(1.0\times10^{-3}\) \(1.0\times10^{-2}\)
\(0.05\) \(2.5\times10^{-4}\) \(1.25\times10^{-3}\)
\(10^{-10}\) \(1.0\times10^{-6}\)
\(5\times10^{-11}\) \(2.1\times10^{-6}\)
\(2.5\times10^{-11}\) \(3.9\times10^{-6}\)
  1. Find the order \(p\) of methods A and B, and the constant \(C\) in error \(\approx C h^p\).
  2. For each of A and B, how small must \(h\) be for an error of \(10^{-8}\) (ignoring rounding)?
  3. What is happening in method C? What would you change?

B3. (the best step) The total error of the forward difference is about \(E(h) = a\,h + \dfrac{b}{h}\) with \(a = |f''|/2\) and \(b = \varepsilon|f|\). (a) Set \(E'(h) = 0\) and show that the best step is \(h^* = \sqrt{b/a}\) and the smallest error is \(E(h^*) = 2\sqrt{ab}\). (b) For the OD curve of the lecture at \(t = 3\) h: \(f = 0.389\), \(|f''| = 0.0592\), \(\varepsilon = 2.2\times10^{-16}\). Compute \(h^*\) and \(E(h^*)\). (The lecture measured an error of \(2.0\times10^{-9}\) at \(h = 10^{-7}\) and \(3.0\times10^{-9}\) at \(h = 10^{-8}\).) (c) For the central difference, \(E(h) \approx c\,h^2 + b/h\). Show that \(h^* \propto \varepsilon^{1/3}\), and estimate it.

B4. (digits per step) Errors of three iterations:

    1. \(0.1,\ 0.05,\ 0.025,\ 0.0125, \ldots\)
    1. \(10^{-1},\ 10^{-2},\ 10^{-4},\ 10^{-8}, \ldots\)
    1. \(0.5,\ 0.45,\ 0.405,\ 0.3645, \ldots\)

For each: linear or quadratic? Give \(c\) (linear) or \(C\) (quadratic). How many steps does (a) need to get from \(0.1\) below \(10^{-10}\)? What is the next error in (b)? How many digits does (c) gain per step, and roughly how many steps does it need to get below \(10^{-10}\)?

B5. (counting operations) Assume \(10^9\) operations per second. (a) For \(n\times n\) matrices \(A\), \(B\) and a vector \(\mathbf x\) with \(n = 20\,000\), count the operations for \((AB)\mathbf x\) and for \(A(B\mathbf x)\). Both give the same vector. How long does each take? (b) How many gene pairs are there for 100 genes, and for 20 000 genes? By what factor does an all-pairs correlation get slower? (c) A clustering step needs the Euclidean distance between every pair of 100 000 cells, each described by 50 principal components. Count the pairs and the operations per distance. How long does it take, and how much memory does a full \(100\,000 \times 100\,000\) distance matrix need?

B6. (doubling experiments) (a) A method takes \(0.40\), \(1.6\) and \(6.5\) s for \(n = 1000, 2000, 4000\). What is \(p\)? Predict the time for \(n = 32\,000\). (b) Another method takes \(0.010\), \(0.011\) and \(0.013\) s for \(n = 10, 20, 40\). What can you conclude about its cost? (c) A colleague’s \(O(n^3)\) method takes 2 s for \(n = 1000\). How long for \(n = 20\,000\)?

B7. (memory) A single-cell atlas has 30 000 genes × 1 000 000 cells. (a) How much memory does it need as a dense matrix of doubles? (b) As a sparse matrix with 5 % non-zeros, at 12 bytes per non-zero? (c) How large is the gene–gene correlation matrix? The cell–cell distance matrix? (d) Why does centring each gene (subtracting its mean) turn (b) into (a)?

C1. (the V) Compute the forward-difference error for \(h = 10^{-1}, 10^{-2}, \ldots, 10^{-15}\) in one vectorised line. Print a table and plot the error against \(h\) on log–log axes. Which \(h\) gives the smallest error? Compare with \(\sqrt{\varepsilon}\) and with your \(h^*\) from B3.

C6. (loops vs vectorised) Compute the dot product of two random vectors of length \(10^7\) with an explicit loop, with an element-wise product and sum, and with a library dot product. Time all three. What is the cost order of each? How much does vectorising buy you in your language?

E1. (the truncation side) With the forward formula, click \(h = 1\), then \(10^{-1}\), then \(10^{-4}\). For each, write down the estimate, the absolute error and the measured slope. In panel (a), why does the secant lie above the tangent at \(h = 1\)? By what factor does the error fall per factor 10 in \(h\), and which constant from the lecture does \(\text{err}/h\) give?

Answer E1

\(h = 1\): estimate \(0.2306\), error \(0.020\) (9.65 %), slope \(0.67\). \(h = 0.1\): \(0.2131\), error \(2.9\times10^{-3}\), slope \(0.98\). \(h = 10^{-4}\): \(0.21026\), error \(3.0\times10^{-6}\), slope \(1.00\). E2. (the rounding side) Keep going: \(10^{-8}\), \(10^{-12}\), \(10^{-15}\), then drag the slider to the far left (\(10^{-16}\)). Record the errors and the measured slopes. What does the estimate become at the end, and what does the readout tell you?

E5. (cost and memory) Open the Cost and memory tab. Click \(n = 100\) genes and read the four times; click \(n \times 2\) a few times and watch how each time grows; then click \(20\,000\). Which operation goes from milliseconds to hours? With \(20\,000\) genes, at how many cells does the dense matrix fill a 16 GB laptop, and up to what fraction of non-zeros is the sparse matrix smaller than the dense one?

Answer E5

At \(n = 100\): dot product 200 ns, matrix–vector 20 µs, gene–gene correlation over 100 000 cells (\(n^2 m = 10^9\) operations) 1 s, matrix–matrix 2 ms. Each doubling of \(n\) multiplies these by 2, 4, 4 and 8. At \(n = 20\,000\): 40 µs, 0.8 s, 11 h and 4.4 h. The matrix–matrix product goes from 2 ms to 4.4 hours, \(200^3 = 8\) million times longer. With 20 000 genes the dense matrix reaches 16 GB at 100 000 cells (\(8 \times 2\times10^4 \times 10^5\) bytes). Sparse storage takes 12 bytes per non-zero against 8 bytes per entry, so it is smaller below \(8/12 = 67\) % non-zeros; at 10 % it needs 2.4 GB.

Hints

Hint 1 — Taylor expansions (B1)

\((1+h)^2 = 1 + 2h + h^2\) and \((1+h)^3 = 1 + 3h + 3h^2 + h^3\). For \((1-h)^3\) flip the sign of the odd powers. In the central difference the even powers cancel.

Hint 2 — the order from two rows (B2)

Halving \(h\) divides an \(O(h^p)\) error by \(2^p\): a factor 4 means \(p = 2\), a factor 8 means \(p = 3\). Then \(C = \text{err}/h^p\) from any row, and \(h = (\text{target}/C)^{1/p}\). If the error grows as \(h\) shrinks, you are on the rounding side of the V.

Hint 3 — the best step (B3)

\(E'(h) = a - b/h^2\). For the central difference \(E'(h) = 2ch - b/h^2\), so \(h^3 = b/(2c)\). Since \(b \propto \varepsilon\), \(h^* \propto \varepsilon^{1/3}\); with \(|f|\) and \(c\) of order one, \(h^* \approx \varepsilon^{1/3}\).

Hint 4 — linear or quadratic (B4)

Compute \(e_{k+1}/e_k\): constant means linear. If not constant, compute \(e_{k+1}/e_k^2\). Digits per step for linear convergence: \(-\log_{10} c\). Steps needed: (digits to gain) / (digits per step).

Hint 5 — counting (B5)

A matrix–vector product is \(2n^2\) operations, a matrix–matrix product \(2n^3\). The number of pairs among \(n\) items is \(n(n-1)/2\). A Euclidean distance in \(d\) dimensions needs \(d\) subtractions, \(d\) multiplications and \(d-1\) additions (the square root is negligible).

Hint 6 — doubling (B6)

Ratio \(= 2^p\), so \(p = \log_2(\text{ratio})\). Going from \(n\) to \(8n\) is three doublings: the time is multiplied by \((2^p)^3\). When the times barely change, ask what else could take 10 ms.

Hint 7 — vectorised derivative and log–log plots (C1, C2)

od(t0 + h) works for a vector h in R and Python, so the whole table is one line; in Rust, h.iter().map(...) does the same. R: plot(h, err, log = "xy"); slope with lm(log10(err) ~ log10(h)). Python: plt.loglog; slope with np.polyfit(np.log10(h), np.log10(err), 1)[0]. Machine epsilon: .Machine$double.eps / np.finfo(float).eps.

Hint 8 — timing (C4, C5, C6)

R: system.time(expr)["elapsed"]; correlation of columns with cor(); counts with rpois; library dot product crossprod. Python: start = time.perf_counter() before and time.perf_counter() - start after; np.corrcoef(X, rowvar=False) correlates columns; counts with rng.poisson; dot product x @ y. Rust: let start = Instant::now(); before and start.elapsed().as_secs_f64() after; Poisson counts with rand_distr::Poisson; matrix and dot products with nalgebra (&a * &b, x.dot(&y)); write the correlation as a loop over gene pairs. If a run takes less than ~0.1 s, the time is mostly overhead.

Hint 9 — sparse matrices (C7)

R: the Matrix package ships with R; rsparsematrix() makes a random sparse matrix, as.matrix() makes it dense. Python: scipy.sparse.random with format="csc"; the storage is S.data.nbytes + S.indices.nbytes + S.indptr.nbytes; S.toarray() makes it dense. Rust: sprs has no random-matrix generator, so build the CSC arrays (indptr, indices, data) yourself and pass them to CsMatI::new_csc; the storage is the length of each array times its element size.

B1. (a) \(h = 0.1\): \((1.21 - 1)/0.1 = 2.1\), error \(0.1\). \(h = 0.01\): \((1.0201 - 1)/0.01 = 2.01\), error \(0.01\). In general \(\big((1+h)^2 - 1\big)/h = 2 + h\), so the error is exactly \(h\). With \(f'' = 2\): \(\tfrac{h}{2}f'' = h\). Taylor’s remainder is exact here because \(f''\) is constant. (b) \((1.21 - 0.81)/0.2 = 0.4/0.2 = 2\): error \(0\). In general \(\big((1+h)^2 - (1-h)^2\big)/(2h) = 4h/(2h) = 2\): the central difference is exact for any quadratic. (c) Forward: \(\big((1+h)^3 - 1\big)/h = 3 + 3h + h^2\), error \(3h + h^2\): \(0.31\) for \(h = 0.1\), \(0.0301\) for \(h = 0.01\). Dividing \(h\) by 10 divides the error by about 10: order 1. Central: \(\big((1+h)^3 - (1-h)^3\big)/(2h) = (6h + 2h^3)/(2h) = 3 + h^2\), error \(h^2\): \(0.01\) for \(h = 0.1\) (\(= (1.331 - 0.729)/0.2 - 3\)), \(10^{-4}\) for \(h = 0.01\). Dividing \(h\) by 10 divides the error by 100: order 2.

B2. (a) A: each halving divides the error by 4, so \(p = 2\); \(C = 4.0\times10^{-3}/0.2^2 = 0.1\). B: each halving divides by 8, so \(p = 3\); \(C = 8.0\times10^{-2}/0.2^3 = 10\). Use a larger \(h\) (for a forward difference around \(10^{-8}\)).

B3. (a) \(E'(h) = a - b/h^2 = 0\) gives \(h^* = \sqrt{b/a}\). Then \(E(h^*) = a\sqrt{b/a} + b\sqrt{a/b} = \sqrt{ab} + \sqrt{ab} = 2\sqrt{ab}\). At the optimum the two errors are equal. The measured errors, \(2\times10^{-9}\) and \(3\times10^{-9}\) on either side of \(h^*\), match. Only about 8 of the 16 digits of a double survive. (c) \(E'(h) = 2ch - b/h^2 = 0\) gives \(h^{*3} = b/(2c)\), so \(h^* = (b/2c)^{1/3} \propto \varepsilon^{1/3} \approx (2.2\times10^{-16})^{1/3} \approx 6\times10^{-6}\). // Least-squares line y = a + b x; returns (intercept, slope), like coef(lm(y ~ x)).
fn fit_line(x: &[f64], y: &[f64]) -> (f64, f64) {
    let n = x.len() as f64;
    let (mx, my) = (x.iter().sum::<f64>() / n, y.iter().sum::<f64>() / n);
    let sxy: f64 = x.iter().zip(y).map(|(xi, yi)| (xi - mx) * (yi - my)).sum();
    let sxx: f64 = x.iter().map(|xi| (xi - mx).powi(2)).sum();
    let b = sxy / sxx;
    (my - b * mx, b)
}

fn main() {
    let t0 = 3.0;

// C4: doubling experiment for the gene-gene correlation matrix.
// Run in release mode, or the timings mean nothing:
//   cargo run -q --release --example convergence_cost_c4
// The correlation is a hand-written loop over all gene pairs (no BLAS, one core),
// so the n^2 scaling shows cleanly. Times depend on your machine; the
// random counts differ from R and Python.
use rand::{rngs::StdRng, SeedableRng};
use rand_distr::{Distribution, Poisson};
use std::hint::black_box;
use std::time::Instant;

// Correlation of the columns of a cells x genes matrix, stored as one Vec per gene.
fn cor(genes: &[Vec<f64>]) -> Vec<Vec<f64>> {
    // centre each gene and scale it to length 1; then correlation = dot product
    let z: Vec<Vec<f64>> = genes.iter().map(|g| {
        let m = g.iter().sum::<f64>() / g.len() as f64;
        let c: Vec<f64> = g.iter().map(|v| v - m).collect();
        let norm = c.iter().map(|v| v * v).sum::<f64>().sqrt();
        c.iter().map(|v| v / norm).collect()
    }).collect();
    let n = z.len();
    let mut r = vec![vec![0.0; n]; n];
    for i in 0..n {
        for j in i..n { // each pair once: n(n+1)/2 dot products of length `cells`
            let s: f64 = z[i].iter().zip(&z[j]).map(|(a, b)| a * b).sum();
            r[i][j] = s;
            r[j][i] = s;
        }
    }
    r
}

fn main() {
    let mut rng = StdRng::seed_from_u64(1);
    let pois = Poisson::new(2.0).unwrap();
    let cells = 1000;
    let genes = [500, 1000, 2000, 4000];
    let mut secs = vec![0.0; genes.len()];
    for (i, &g) in genes.iter().enumerate() {
        let x: Vec<Vec<f64>> = (0..g)
            .map(|_| (0..cells).map(|_| pois.sample(&mut rng)).collect())
            .collect(); // cells x genes, one Vec per gene
        let start = Instant::now();
        black_box(cor(black_box(&x)));
        secs[i] = start.elapsed().as_secs_f64();
    }
    println!("{:?}", secs.iter().map(|s| (s * 1000.0).round() / 1000.0).collect::<Vec<_>>());
    println!("{:?}", secs.windows(2).map(|w| (w[1] / w[0] * 100.0).round() / 100.0).collect::<Vec<_>>());
    // slope of log10(secs) against log10(genes), by least squares
    let lx: Vec<f64> = genes.iter().map(|&g| (g as f64).log10()).collect();
    let ly: Vec<f64> = secs.iter().map(|s| s.log10()).collect();
    let (mx, my) = (lx.iter().sum::<f64>() / 4.0, ly.iter().sum::<f64>() / 4.0);
    let slope = lx.iter().zip(&ly).map(|(a, b)| (a - mx) * (b - my)).sum::<f64>()
        / lx.iter().map(|a| (a - mx).powi(2)).sum::<f64>();
    println!("{slope}");
    println!("{}", secs[3] * (20000.0 / 4000.0_f64).powi(2) * (100000.0 / cells as f64) / 3600.0); // hours
}

In R the ratios are close to 4 and the slope is \(2.01\): quadratic in genes, as predicted by the pair count. The extrapolation (quadratic in genes, linear in cells) gives about 7.6 hours for 20 000 genes × 100 000 cells. For 100 genes the same rule gives \(0.167 \times (100/500)^2 \times 100 \approx 0.7\) s.

In Python, np.corrcoef uses an optimised multi-threaded matrix product and is far faster, but the fitted slope (\(1.3\)) is too low: the smallest runs take about 10 ms, where overhead dominates, and more cores join in as \(n\) grows. Larger sizes push the slope towards 2; with genes = [1000, 2000, 4000, 8000] the same machine gave times [0.019 0.119 0.254 0.711] and slope \(1.68\). Trust only an exponent from runs long enough to measure, and use \(p = 2\) from the operation count for the extrapolation: about 8 minutes on this machine. R’s cor() is slow because it does not use the optimised library; a correlation via crossprod(scale(X)) was about 20 times faster here. A better constant, the same exponent.

The Rust version is a hand-written loop over gene pairs on a single core (no BLAS). It gave ratios near 4, slope \(2.04\) and about 7.4 hours for the full data set: close to R’s cor(). Its times, like all of these, depend on the machine.

The results agree to rounding error (\(\sim 10^{-15}\) relative). \(A(B\mathbf x)\) is about 8–12 times faster in the example runs above, not the \(n/2 = 1000\) times the operation count predicts for \(n = 2000\). The reason: the matrix–matrix product is the most optimised routine in numerical computing (it reuses data in the cache and uses all cores), so it runs at many more operations per second than a matrix–vector product. Operation counts predict how the time grows, not the constant. With one thread (OPENBLAS_NUM_THREADS=1) the R gap on this machine grew to about 25×, and it grows with \(n\): at \(n = 20\,000\) the difference is hours against a second. Rust with nalgebra (single-threaded, no BLAS) showed about 60× between \((AB)\mathbf x\) and \(A(B\mathbf x)\): closer to the 1000× of the operation count, because no multithreaded BLAS speeds up the matrix–matrix product.

// rust/examples/convergence_cost_c7.rs  —  cargo run --example convergence_cost_c7
// C7: memory of dense and sparse matrices.
// Sparse storage with sprs (compressed sparse column, 4-byte u32 indices as in R/scipy).
// The random matrix differs from R and Python, but the sizes do not.
use rand::{rngs::StdRng, seq::index, SeedableRng};
use rand_distr::{Distribution, Poisson};
use sprs::CsMatI;
use std::mem::size_of;

fn main() {
    let x = vec![0.0_f64; 1000 * 1000]; // a 1000 x 1000 matrix of zeros, stored as one Vec
    println!("{}", x.len() * size_of::<f64>());
    println!("{} {}", 20000.0 * 100000.0 * 8.0 / 1e9, 20000.0_f64.powi(2) * 8.0 / 1e9); // GB

    // genes x cells, 10 % non-zeros: in each cell, 200 random genes get count Poisson(2) + 1
    let (genes, cells, per_cell) = (2000, 10000, 200);
    let mut rng = StdRng::seed_from_u64(1);
    let pois = Poisson::new(2.0).unwrap();
    let mut indptr = vec![0u32];
    let (mut indices, mut data) = (Vec::new(), Vec::new());
    for _ in 0..cells {
        let mut rows = index::sample(&mut rng, genes, per_cell).into_vec();
        rows.sort(); // CSC wants sorted row indices within a column
        for r in rows {
            indices.push(r as u32);
            data.push(pois.sample(&mut rng) + 1.0);
        }
        indptr.push(indices.len() as u32);
    }
    let s = CsMatI::new_csc((genes, cells), indptr, indices, data);
    let sparse_bytes = s.data().len() * size_of::<f64>()
        + s.indices().len() * size_of::<u32>()
        + s.indptr().raw_storage().len() * size_of::<u32>();
    let dense_bytes = genes * cells * size_of::<f64>(); // what s.to_dense() would take
    println!("{} {}", dense_bytes as f64 / 1e6, sparse_bytes as f64 / 1e6); // MB

    // centre each gene: every zero becomes -mean, so the result must be dense
    let mut row_sum = vec![0.0; genes];
    for (&v, (r, _c)) in s.iter() {
        row_sum[r as usize] += v; // u32 index -> usize to index a Vec
    }
    let mut sc = vec![0.0_f64; genes * cells]; // dense, column-major
    for c in 0..cells {
        for r in 0..genes {
            sc[c * genes + r] = -row_sum[r] / cells as f64;
        }
    }
    for (&v, (r, c)) in s.iter() {
        sc[c as usize * genes + r as usize] += v;
    }
    println!("{}", sc.len() * size_of::<f64>() / 1_000_000); // MB
}
