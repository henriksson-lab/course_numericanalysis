Exercise: how computers store numbers

Goal

By the end of this exercise you should be able to:

  • convert small whole numbers and fractions between decimal and binary, and explain why 0.1 cannot be stored exactly,
  • explain what an IEEE double stores (sign, exponent, fraction) and why it has about 16 significant digits,
  • find the gap between neighbouring doubles near a given number, and state machine epsilon,
  • predict when a computation will overflow (Inf), underflow (0) or give NaN,
  • compare floating-point numbers with a tolerance instead of ==,
  • compute a likelihood on the log scale, add probabilities with log-sum-exp, and use log1p/expm1 for small rates.

The by-hand part uses pen, paper and (for exp and log in B6 and B7) a pocket calculator. The code part checks your hand answers and then works at sizes where only code works.

Background

A double (R’s numeric, Python’s float, numpy’s float64) stores a number as

\[x = \pm\, 1.f \times 2^{e}\]

in 64 bits: 1 sign bit, 11 bits for the exponent \(e\) (from \(-1022\) to \(1023\)) and 52 bits for the fraction \(f\). With the hidden leading 1 that is 53 significant bits, about 15–16 decimal digits.

Facts used below:

  1. Binary. Whole numbers: divide by 2 repeatedly, read the remainders bottom-up. Fractions: multiply by 2 repeatedly, the integer parts are the bits. A fraction ends in binary only if its denominator is a power of 2; \(0.1 = 0.0\overline{0011}_2\) repeats forever, so it is rounded.
  2. Machine epsilon \(\varepsilon = 2^{-52} \approx 2.2\times10^{-16}\) is the gap between 1 and the next double. Each arithmetic operation returns the exact result rounded to the nearest double, with relative error at most \(\varepsilon/2\).
  3. Gap near \(x\): \(2^{\lfloor \log_2|x| \rfloor - 52} \approx \varepsilon |x|\). The relative gap is constant; the absolute gap grows with \(|x|\).
  4. Range. Largest double \(\approx 1.8\times10^{308}\) (above: Inf, overflow). Smallest normal double \(\approx 2.2\times10^{-308}\); subnormal numbers go down to \(4.9\times10^{-324}\) with fewer digits; below that: 0, underflow. exp(x) overflows for \(x > 709.8\) and underflows for \(x < -745\).
  5. Special values. 1/0 = Inf, log(0) = -Inf, 0/0 = NaN, Inf - Inf = NaN. None of these gives an error or (in R) a warning.
  6. Integers. Doubles store every whole number exactly up to \(2^{53}\approx 9.0\times10^{15}\). R’s integer type (5L) is 32 bits, maximum \(2^{31}-1 = 2\,147\,483\,647\); overflow gives NA.
  7. Log-likelihoods. \(\log \prod_i p_i = \sum_i \log p_i\). To add probabilities stored as logs \(a_k = \log x_k\), use log-sum-exp: with \(m = \max_k a_k\), \[\log \sum_k e^{a_k} = m + \log \sum_k e^{a_k - m}.\]
  8. Small arguments. log1p(x) \(= \log(1+x)\) and expm1(x) \(= e^x - 1\) stay accurate when \(|x| \ll 1\), where log(1 + x) and exp(x) - 1 lose digits.

By hand

B1. Binary integers. (a) Convert 6, 13, 37 and 255 to binary. (b) Convert \(10110_2\) and \(1000000_2\) to decimal. (c) How many bits does it take to write 255? What is the largest whole number you can write with 8 bits?

B2. Binary fractions. (a) Convert 0.75, 0.3125 and 5.375 to binary. (b) Run the “multiply by 2” recipe on 0.2 for 8 steps. Show that the bits repeat and write 0.2 as a repeating binary fraction. (c) Without a computer: is 0.5 + 0.25 == 0.75 TRUE or FALSE in R? What about 0.1 + 0.7 == 0.8? Explain the difference.

B3. A toy floating-point system. Imagine a computer that stores numbers as \(1.f_1f_2f_3 \times 2^e\): 3 fraction bits, exponent \(e \in \{-1, 0, 1, 2\}\) (the picture on the “Floats are not evenly spaced” slide). (a) List all the numbers this system has in \([2, 4)\). (b) What is the gap between neighbouring numbers in \([1, 2)\)? In \([4, 8)\)? (c) Round 1.3, 5.3 and 6.2 to the nearest number in the system. Give the relative error of each. (d) What is machine epsilon for this system? What is the largest possible relative rounding error? (e) What is \(1 + 0.1\) in this system? And \(1 + 0.05\)? (f) What is the largest number in the system? What happens to \(7.5 + 4\)?

B4. The gap between doubles. Use \(\text{gap}(x) = 2^{\lfloor \log_2|x| \rfloor - 52}\). (a) Find the gap near \(x = 1\), \(1000\), \(0.001\), \(3.1\times10^9\) (a position in a concatenated human genome) and \(10^{16}\). First find the power of 2 just below each \(x\). (b) Is 1e16 + 1 == 1e16 TRUE or FALSE? (c) A genome browser stores the position \(3\,100\,000\,000.5\) (a point between two bases) as a double. Is it stored exactly? (d) For each \(x\) in (a), compute gap\((x)/x\). What do you notice?

B5. Spot the overflow and underflow. For each computation, say whether a double gives a normal number, Inf, 0 or NaN. Estimate the true value with powers of 10. (a) 1e200 * 1e200 (b) 1e-200 * 1e-200 (c) 0.01^200 (d) exp(1000) (e) factorial(200) (use \(200! \approx 7.9\times10^{374}\)) (f) 1e300 * 1e10 / 1e20 and 1e300 / 1e20 * 1e10 (g) The probability that 2000 reads all map correctly, if each maps correctly with probability 0.999: 0.999^2000. (Use \(\ln 0.999 \approx -0.001\).) (h) The likelihood of 2000 reads, each with probability \(10^{-3}\) under model 1: (1e-3)^2000. (i) The likelihood ratio of model 1 against model 2 (each read probability \(2\times10^{-3}\)): (1e-3)^2000 / (2e-3)^2000. What is the log of the true ratio?

B6. Log-sum-exp by hand. Use a calculator for exp and log (natural log). Useful values: \(e^{-1} = 0.3679\), \(e^{-2} = 0.1353\), \(e^{-12} = 6.14\times10^{-6}\), \(\ln 3 = 1.0986\). (a) Compute \(\log(e^{-500} + e^{-502})\) with the log-sum-exp formula. Then compute the two “posterior” weights \(e^{a_k} / \sum_j e^{a_j}\). (b) Compute \(\log(e^{2} + e^{2} + e^{2})\). Check against a simple rule. (c) Genotype calling. At one site, the log-probabilities \(\log P(\text{reads} \mid g) + \log P(g)\) for the genotypes AA, AB, BB are \(-1200\), \(-1198\) and \(-1210\). Compute \(\log P(\text{reads})\) and the posterior probability of each genotype. (d) Why does log(sum(exp(a))) fail for the numbers in (c)? (e) What would go wrong if you pulled out the smallest \(a_k\) instead of the largest, for \(a = (-1000, 0)\)?

B7. Small rates. (a) Use the Taylor polynomial \(\log(1+x) \approx x - x^2/2\) to compute \(\log(1 + 10^{-10})\) to 11 significant digits. (b) The computer first rounds \(1 + 10^{-10}\) to the nearest double (gap \(\varepsilon \approx 2.2\times10^{-16}\) near 1). How large can the error in the stored \(1 + x\) be, relative to \(x\)? About how many significant digits of \(\log(1 + 10^{-10})\) can log(1 + x) get right? (c) What does log(1 + 1e-17) return, and why? (d) A mutation rate is \(\mu = 10^{-9}\) per site per generation. Use \(e^{-\mu} \approx 1 - \mu + \mu^2/2\) to compute \(P(\text{at least one mutation}) = 1 - e^{-\mu}\) to 10 significant digits.

B8. Integers. (a) The human genome is about \(3.1\times10^9\) bp. Can a position on the concatenated genome be stored in R’s integer type? In a double? (b) A single-cell count matrix has 20 000 genes and 100 000 cells. Does the number of entries fit in a 32-bit integer? What about 30 000 genes? (c) Is \(2^{53} + 1\) a double? What does 2^53 + 1 - 2^53 return?

In code

C1. See the stored numbers. (a) Print 0.1, 0.25, 0.3, 1/3 and 0.5 with 20 decimals. Which are exact? Does that match B2? (b) Add 0.1 to itself ten times in a loop, starting from 0. Is the result == 1? Print it with 20 decimals, then compare with a tolerance.

C2. Machine epsilon and the gap. (a) Find machine epsilon yourself: start with eps <- 1 and halve it while 1 + eps / 2 != 1. Compare with the built-in value. (b) Write a function gap(x) from the formula and check your answers to B4(a). (Python: compare with np.spacing.) (c) Check B4(b) in code.

C3. A grid of concentrations. A dose–response experiment uses the concentrations seq(0, 1, by = 0.1) (Python: np.arange(0, 1.05, 0.1)). You want the index of concentration 0.3. (a) Try which(conc == 0.3) (Python: np.where(conc == 0.3)[0]). What happens? (b) Write a function near(a, b, tol) that returns TRUE when \(|a - b| \le \text{tol}\cdot\max(|a|, |b|, 1)\), and use it to find the index.

C4. Overflow, underflow and integers. (a) Check all your answers to B5 (a)–(i) in code (for (e), R has factorial; in Python use np.exp(1000.0) for (d) and skip (e)). (b) Store the lengths of human chromosomes 1–13 (GRCh38, given in the solution below) as R integers (Python: np.int32), and take the cumulative sum. Where does it go wrong? Fix it.

C5. Underflow in a likelihood. UMI counts of one gene in 10 000 cells are modelled as Poisson with mean \(\lambda\). Use the counts rep(c(2, 4, 3, 1, 5, 3, 2, 6, 3, 2), 1000). (a) For each \(\lambda\) on the grid seq(2, 4, by = 0.01), compute the likelihood \(\prod_i P(\text{count}_i \mid \lambda)\) with dpois (Python: scipy.stats.poisson.pmf). Which \(\lambda\) has the largest likelihood? (b) Do the same with the log-likelihood, using dpois(..., log = TRUE) (Python: poisson.logpmf). Which \(\lambda\) now? Compare with the mean of the counts (the exact maximum-likelihood estimate). (c) How many cells does it take before the product of the first \(n\) likelihoods (at \(\lambda = 3\)) underflows? Try \(n = 300\) and \(n = 400\).

C6. Log-sum-exp. (a) Write logsumexp(a). Make it return -Inf when every element is -Inf (otherwise m - m gives NaN). (b) Check B6 (a)–(c). In Python, also compare with scipy.special.logsumexp. (c) Genotype calling from 2000 reads. At a site with \(n = 2000\) reads, \(k = 1010\) show the alternative base. With sequencing error rate 0.01, the probability that a read shows the alternative base is \(q = 0.01\) (genotype AA), \(0.5\) (AB) or \(0.99\) (BB). For fixed reads, \(\log P(\text{reads} \mid g) = k \log q + (n-k)\log(1-q)\). Add the log prior \(\log(0.25, 0.5, 0.25)\), then compute \(\log P(\text{reads})\) both naively and with logsumexp, and the posterior of each genotype.

C7. expm1 and log1p. For \(\mu = 10^{-3}, 10^{-4}, \dots, 10^{-17}\), compute \(1 - e^{-\mu}\) naively and with expm1 (Python: np.expm1). Print the relative difference. From which \(\mu\) on is the naive version useless? Compare with B7(b).

Explore

The inspector below shows the 64 bits of a double, coloured as on the lecture slide: sign, 11 exponent bits, 52 fraction bits. Type a number or a short expression (+ - * / ^, eps) and press Enter, or click a preset. Clicking a bit flips it. On the left, stored exactly is the complete decimal value of the stored binary number; on the right, the number line shows the stored double (blue), its neighbours (grey) and, as an orange ▲, the exact value before rounding: the number you typed, or the exact result of the last operation on the already stored operands.

E1. Why 0.1 + 0.2 != 0.3. Click 0.1, 0.2 and 0.3 in turn. Is each stored number above or below what you typed, and by what fraction of a gap? Then click 0.1+0.2. Where does the orange ▲ (the exact sum of the stored 0.1 and 0.2) lie, which neighbour is the stored 0.3, and why was the sum rounded up rather than down?

Answer E1

0.1 and 0.2 are stored slightly too large (0.1000000000000000055511…, 0.2000000000000000111…), each 0.400 gaps above the typed value; 0.3 is stored slightly too small (0.29999999999999998889…), 0.200 gaps below. The exact sum of the stored 0.1 and 0.2 is 0.3000000000000000166533…, which lies exactly halfway (0.500 gaps) between two doubles: the one below is 0.29999999999999998890, the stored 0.3, and the one above is 0.30000000000000004441. A tie goes to the neighbour whose last fraction bit is 0, and that is the upper one (the stored 0.3 ends in …0011, the upper one in …0100). So the sum lands one gap (\(2^{-54} \approx 5.55\times10^{-17}\)) above the stored 0.3. Each individual rounding is tiny (relative error \(5.55\times10^{-17}\) for 0.1, \(9.25\times10^{-17}\) for the sum, both below \(\varepsilon/2\)), but == asks for the same bits.

E2. The gap. Read gap to next double and relative gap for 1, 1+ε, the chromosome 1 length 248956422, 2^53 and 2^53+1. Also read the two gaps under the number line for 1 and for 2^53. What happens to the absolute and to the relative gap? What does 2^53+1 become, and why?

Answer E2

At 1 the gap above is \(2^{-52} \approx 2.22\times10^{-16} = \varepsilon\), but the gap below 1 is only \(1.11\times10^{-16}\): 1 is a power of 2, where the spacing changes. 1+ε is the next double after 1 (the last fraction bit is 1). 248956422 is stored exactly (all whole numbers below \(2^{53}\) are); its gap is \(2^{-25} \approx 2.98\times10^{-8}\), relative gap \(1.20\times10^{-16} = 0.539\,\varepsilon\). At \(2^{53}\) the gap below is 1 and the gap above is 2. The absolute gap grows with \(x\), while the relative gap always stays between \(\varepsilon/2\) and \(\varepsilon\) (B4). 2^53+1 is exactly halfway between \(2^{53}\) and \(2^{53}+2\) (the ▲ is 0.500 gaps above), and the tie goes to \(2^{53}\), whose last bit is 0: 2^53 + 1 == 2^53.

E3. Flip bits. Click the preset 1. (a) Flip the last (rightmost) fraction bit. Which preset do you get? (b) Click 1 again and flip the rightmost exponent bit. Then flip the leftmost exponent bit instead. (c) From there, flip any fraction bit. Explain each result from the formula \((-1)^s \times 1.f \times 2^{e}\).

Answer E3
  1. 1.0000000000000002 = 1+ε: the last fraction bit is worth \(2^{-52}\). (b) 1 has exponent field \(01111111111_2 = 1023\), so \(e = 0\). Flipping the rightmost exponent bit gives 1022, \(e = -1\), so \(x = 0.5\). Flipping the leftmost one instead gives \(11111111111_2 = 2047\), the reserved “all ones” exponent: with fraction 0 that is Inf. (c) All-ones exponent with a nonzero fraction is NaN. Inf and NaN are ordinary bit patterns, which is why arithmetic can produce them silently (no error, no warning).

E4. The ends of the range. Click 5e-324 and then 1e30810. For 5e-324: what kind of number is stored, how many significant bits does it have, and how large is the rounding error of the typed value? For 1e30810: what is the exact result and what is stored? Finally, the per-site likelihoods in the lecture are around 0.2 (\(\log_{10} 0.2 \approx -0.7\)): roughly after how many sites does a product of them fall below this smallest double?

Answer E4

5e-324 is stored as \(4.9406564584124654\times10^{-324} = 2^{-1074}\), the smallest subnormal: exponent field 0, and a single 1 in the last fraction bit, so only 1 significant bit. The relative gap is 1 (\(4.5\times10^{15}\,\varepsilon\)), and the typed 5e-324 is rounded with a relative error of 1.19%, far above \(\varepsilon/2\): subnormals trade precision for range. 1e308*10: the exact product of the stored 1e308 and 10 is \(1.0000000000000000110\ldots\times10^{309}\), larger than the largest double \(1.797\ldots\times10^{308}\), so the result is Inf (exponent all ones), with no warning. Below about half of \(4.9\times10^{-324}\) (\(\log_{10} \approx -323.6\)) a product rounds to 0, so at \(-0.7\) decades per site it takes about \(323.6/0.7 \approx 460\) sites, close to the 470 sites for the simulated alignment on the “Back to the likelihood” slide.

Hints

Hint 1 — decimal to binary (B1, B2)

Whole part: divide by 2 and keep the remainders; the last remainder is the first bit. Fraction part: multiply by 2; the integer part (0 or 1) is the next bit, then drop it and continue with the fraction. For 5.375, do 5 and 0.375 separately and join them with a binary point. To check, add up the place values (\(2^2, 2^1, 2^0, 2^{-1}, \dots\)).

Hint 2 — the toy system (B3)

Between \(2^e\) and \(2^{e+1}\) there are \(2^3 = 8\) numbers, evenly spaced with gap \(2^e/8\). Machine epsilon is the gap just above 1. To round, find the two neighbours and pick the closer one.

Hint 3 — the gap near x (B4)

Find the integer \(k\) with \(2^k \le |x| < 2^{k+1}\): \(2^9 = 512\), \(2^{10} = 1024\), \(2^{-10} \approx 0.000977\), \(2^{31} \approx 2.15\times10^9\), \(2^{53} \approx 9.0\times10^{15}\). The gap is \(2^{k-52}\). In code: 2^(floor(log2(abs(x))) - 52) in R; np.spacing(x) in Python.

Hint 4 — overflow and underflow (B5)

Work with powers of 10: a double is between about \(10^{-308}\) (or \(10^{-324}\) with subnormals) and \(10^{308}\). For powers, \(a^n = 10^{n \log_{10} a}\), or \(e^{n \ln a}\). Operations are done left to right, so the order in (f) matters. In (i), what is \(0/0\)?

Hint 5 — log-sum-exp (B6, C6)

Subtract the largest \(a_k\) from every \(a_k\), exponentiate (now the largest term is \(e^0 = 1\)), add, take the log, and add the largest \(a_k\) back. The posterior weights are \(e^{a_k - \text{LSE}}\), where LSE is the log-sum-exp; they add up to 1. In R, max, exp, sum, log; in Python, np.max, np.exp, np.sum, np.log, or scipy.special.logsumexp.

Hint 6 — comparing with a tolerance (C1, C3)

R: all.equal(a, b) returns TRUE or a description of the difference, so use isTRUE(all.equal(a, b)) in an if. Python: math.isclose(a, b) for single numbers, np.isclose(a, b) for arrays. For your own near, use abs and pmax (R) or np.abs and np.maximum (Python). See sprintf (R) or an f-string f"{x:.20f}" (Python) to print digits.

Hint 7 — limits of the number system (C2, C4)

R: .Machine has double.eps, double.xmax, double.xmin and integer.max. Python: np.finfo(float) has .eps, .max, .tiny, .smallest_subnormal; np.iinfo(np.int32) has .max. Convert integers to doubles with as.numeric() (R) or .astype(np.float64) (Python). Check results with is.finite / np.isfinite.

Hint 8 — log-likelihoods (C5)

// index of the FIRST largest value, like R's which.max and np.argmax
fn which_max(v: &[f64]) -> usize {
    let mut best = 0;
    for i in 1..v.len() {
        if v[i] > v[best] {
            best = i;
        }
    }
    best
}

fn main() {
    let base: [u64; 10] = [2, 4, 3, 1, 5, 3, 2, 6, 3, 2];
    let counts: Vec<u64> = base.repeat(1000);                  // 10 000 cells
    let lambda: Vec<f64> = (0..=200).map(|i| 2.0 + i as f64 * 0.01).collect();

    // likelihood (product) and log-likelihood (sum) for one lambda
    let lik = |l: f64, x: &[u64]| {
        let p = Poisson::new(l).unwrap();
        x.iter().map(|&k| p.pmf(k)).product::<f64>()
    };
    let loglik = |l: f64, x: &[u64]| {
        let p = Poisson::new(l).unwrap();
        x.iter().map(|&k| p.ln_pmf(k)).sum::<f64>()
    };
    let liks: Vec<f64> = lambda.iter().map(|&l| lik(l, &counts)).collect();
    let logliks: Vec<f64> = lambda.iter().map(|&l| loglik(l, &counts)).collect();

    let min = liks.iter().cloned().fold(f64::INFINITY, f64::min);
    let max = liks.iter().cloned().fold(f64::NEG_INFINITY, f64::max);
    println!("{} {}", min, max);
    println!("{:.2}", lambda[which_max(&liks)]);
    println!("{:.2}", lambda[which_max(&logliks)]);

The relative error grows roughly like \(\varepsilon/\mu\), as B7(b) predicts: about \(10^{-8}\) at \(\mu = 10^{-9}\) (half the digits gone), \(10^{-4}\) at \(\mu = 10^{-13}\), and 100% from \(\mu \approx 10^{-16}\) on, where \(e^{-\mu}\) rounds to exactly 1. The rule: whenever you compute \(1 - e^{-x}\), \(e^x - 1\) or \(\log(1 \pm x)\) with a small \(x\), use expm1/log1p.

Where this leads

  • Error, conditioning and stability (unit 3): we measure errors as absolute and relative errors, and study catastrophic cancellation (B7 and the subtraction slide are first examples) and the condition number, which says how much a problem magnifies the rounding errors of this unit.
  • Convergence and cost (unit 4): machine epsilon sets a floor. On an error-vs-step-size plot, errors stop falling at around \(10^{-16}\) (or much earlier) because of rounding; that is the trade-off between truncation and rounding error.
  • Stopping tolerances in root finding (Bisection and fixed-point iteration, Part 2) and optimisation (Part 9) are chosen relative to \(\varepsilon\), and the likelihoods we maximise are always log-likelihoods, for the reasons in C5: Newton and secant methods finds a Poisson rate from UMI counts by Newton on the log-likelihood’s derivative, using expm1.
